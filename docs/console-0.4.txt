Vatex LUMINA 0.4.0 콘솔 운영 안내
=================================

0.4.0은 현재 Windows 검토용 최신 버전이다. README의 0.3·0.2와 구형 Horizon
설명은 당시 이력이다. 0.4는 시각 콘솔과 제한된 XDR 근거 연결을 확장했으며,
Splunk 또는 다른 상용 SIEM 전체와 동등하거나 우월함을 입증한 버전은 아니다.
ISO 빌드·배포와 외부 Release 발행 완료를 뜻하지 않는다.

시작과 공통 조작
----------------
로그인한 뒤 왼쪽 메뉴에서 작업 공간을 선택한다. 상단 조회 기간은 최근 1시간,
24시간 또는 7일이다. Ctrl+K로 화면을 찾거나 텍스트 로그 검색으로 이동한다.
조회 기간은 명령센터·로그·자산 관계·대시보드·XDR 같은 기간 조회에 적용한다.
케이스 목록과 설정 편집은 해당 목록·정의의 기준을 따르며 기간 필터가 아니다.
폼·템플릿을 열어도 설정이나 동작을 자동 저장하지 않는다. 저장, 평가, 실행 요청과
승인 버튼의 효과를 구분한다. 기본 작업은 필드·행·단계 편집 폼을 사용한다.
원문 JSON, SPL, 파일 가져오기·내보내기는 조사·호환을 위한 전문가 경로다.

Command Center
--------------
명령센터는 현재 권한으로 실제 조회한 수신 이벤트, 탐지 결과, 사건, 관측 호스트,
등록 자산과 소스 상태를 표시한다. 이 화면만 10초 간격으로 다시 조회한다.
화면을 떠나거나 로그아웃하면 해당 갱신을 정리한다. 다른 편집 화면은 자동으로
반복 실행하지 않는다. 조회 실패는 마지막 성공 자료와 오류로 표시한다.
수집이나 사건이 없으면 0건과 빈 상태를 표시하며 연결·위험·성공 수치를 만들어 넣지 않는다.

수신 추이는 received 기준이고 사건은 선택 기간에 생성된 사건 집합이다. 저장
페이로드 크기는 raw와 message의 저장 UTF-8 바이트 합계로 네트워크 전송량이 아니다.
열린 사건은 현재 new/triage 상태다. SLA는 명시한 due_at이 있는 사건만 계산하며
현재 열린 사건의 기한 초과를 확인한다. 심각도는 사건 전체에 기록된 탐지 근거의
최대 심각도다. 관측 호스트와 운영자가 등록한 자산은 별도로 집계한다.

응답 흐름은 실행 중, 승인 대기, 확인 필요, 완료된 플레이북, 수동 조치, 미처리 중
하나로 사건을 분류한다. 실행·대기·오류 기록을 완료보다 우선한다. 완료된 플레이북이
있어도 사건이 해결되었거나 엔드포인트가 격리된 것은 아니다. 목록 표본과 전체
권한 집합의 집계를 구분한다. 분석 저장소와 제어 저장소는 별도의 읽기 스냅샷이다.

작업 공간
---------
사건: 상태·심각도로 목록을 좁히고 개요, 타임라인, 근거 그래프, 작업, 실행 탭을
사용한다. 메모·우선순위·마감·북마크를 기록한다. 필수 작업이 남아 있으면 사건
종료가 거부된다. 저장 검색 탐지 결과는 별도 목록이며 상관 사건과 중복 합산하지 않는다.
사건 타임라인·그래프는 현재 근거 페이지에 한정된다. 그래프는 저장된 엔터티·정책·
이벤트 근거 관계이며 네트워크 연결이나 인과관계를 추론하지 않는다.

탐지 정책: 엔터티 필드, 시간 범위, 간격, 늦은 이벤트 대기, 심각도·위험 기여도와
순서형 이벤트 단계를 구성한다. 미리보기는 실제 검색하되 탐지 결과를 저장하지 않는다.
과거 구간 재평가는 탐지 결과를 기록하므로 종료 시간을 확인한다. 기존 정의를 여는
편집기는 새 정책으로 복제하며, 버전 전환에는 콘텐츠 패키지를 사용한다.

플레이북: 동작 팔레트에서 메모, 작업, 담당자, 상태, 허용된 웹훅을 추가하고 순서를
바꾼다. 현재는 순차 실행이며 분기, DAG, 탐지 자동 트리거는 지원하지 않는다.
정의 저장과 실행 요청은 다르다. 케이스에 실행을 요청한 뒤 요청자와 다른 활성
분석가 또는 관리자가 승인해야 실행된다. 요청 당시 정의·범위·근거를 고정하고
승인 및 실행 때 권한을 다시 확인한다. 결과 불명은 운영자가 실제 외부 결과를
확인해야 한다. 외부 전송 대상은 서버의 명시적 HTTPS 허용 목록으로 구성하며
기본 비활성이다. 전송 값은 고정된 내용이고 자동 이벤트 변수 치환은 없다.

수집·데이터: 정확한 소스 이름, JSON 메시지 해석, 필드 매핑·마스킹, 필수 필드와
라우팅을 폼으로 구성한다. 예제 미리보기는 수집하지 않는다. 중첩 값만 마스킹하면
원본 message 문자열에 같은 값이 남을 수 있으므로 원문까지 제거하려면 message도
지정한다. 격리 사본의 삭제된 값은 재처리로 복원하지 않는다. 소스 모니터의 정상은
설정한 운영 기준을 만족했다는 뜻이며 공격 부재나 수집 완전성 보증이 아니다.

자산·행동: 직접 확인한 별칭·인덱스·중요도를 등록하고 같은 이벤트에서 함께 관측된
필드 관계를 조사한다. 행동 기준선은 시간 버킷 빈도 z-score, 새로운 엔터티·호스트와
명시한 UTC 업무 시간 이탈을 비교한다. 준비에 필요한 표본이 없으면 준비 중이다.
고급 ML, peer 모델, 공격 확정, 자동 사건 생성 기능으로 표시하지 않는다.

대시보드: 검색, 막대·숫자·표 패널을 시각 폼으로 구성한다. 숫자·문자 조건과 기존
투영·다중 그룹·정렬을 구분해 보존한다. 실제 API의 사전형 행과 호환 배열형 행을
동일한 열 순서로 처리한다. 결과 한도에 도달하면 더 많은 결과가 있을 수 있다.

콘텐츠: 필수 소스·필드, 규칙, 예제 이벤트와 기대 엔터티를 편집한다. 구조·권한 확인,
불변 리비전 저장, 양성·음성 테스트, 최근 실제 필드 확인을 거친 뒤 관리자가 게시한다.
게시·롤백은 현재 활성 리비전 확인 후 실제 상관 정책을 원자 전환한다. 테스트 통과와
필드 존재는 실제 환경의 탐지율·오탐률 인증이 아니다. 순서형 상관 패키지 부분집합이며
범용 Sigma 의미를 조용히 단순화하지 않는다.

참조표·TI: 열·행·고유 키를 편집하며 문자, 숫자, boolean, null과 필드 없음을
보존한다. IP·도메인·MD5/SHA1/SHA256 지표는 출처, 신뢰도와 만료를 요구한다.
큰 정수 등 브라우저에서 정확히 보존할 수 없는 값이 있으면 저장을 차단한다.
외부 피드 자동 수집, 표 삭제 API와 CSV 일괄 편집을 제공한 것으로 해석하지 않는다.

운영·설정: 대기열, 실행 실패·지연, 보존, 감사 검증, 가입 제어면과 구성 여부를
확인한다. 사용자·역할·정확한 인덱스 범위와 본인 비밀번호·MFA를 관리한다.
운영 화면의 장비 가입은 자동 데이터 복제·샤딩·Master 승격이나 장비 HA를 뜻하지 않는다.
검색 연합과 원격 XDR은 실제 서버 설정이 있어야 사용한다.

XDR의 실제 범위
---------------
제공된 AEGIS XDR 원본 에이전트는 인벤토리·프로세스 수집을 지원한다. VATEX는
인증된 이벤트 수입, 프로세스 GUID의 센서 보고 부모 관계와 조회 창 내부의 연결
트리 투영을 제공한다. PID만으로 프로세스를 합치지 않는다. 투영 세션은 AEGIS의
영속 세션 생명주기나 네트워크 인과관계를 복제한 것이 아니다.

원격 브리지는 명시적 HTTPS·인증·테넌트 및 인덱스·호스트 바인딩을 사용하는 읽기
전용 요약 경로이며 기본 미구성이다. 자동 이벤트 수입은 없다. isolate_host와
release_host는 원본 에이전트에 구현되지 않았으므로 비활성으로 표시한다.
명령 전송, 임의 셸, 실제 호스트 격리를 성공한 것처럼 표시하지 않는다.

주요 API와 실제 한도
-------------------
GET /api/console/summary?start=&end=
  기본 최근 24시간, 최대 366일, 미래 조회 제한, 전체 요청 5초 예산.
  48개 시간 버킷, 최근 사건 최대 50개·소스 행 100개. 전체 집계와 행 표본은 별도다.
POST /api/search
  반환 1–1000행, 출력 최대 2MiB, JSON 조건 최대 20개·투영 12개·그룹 3개.
  검색 동시 슬롯과 timeout은 서버 설정을 따른다. 기본 timeout은 15초다.
GET /api/incidents, /api/findings
  사건 목록 최근 수정순 200개. 저장 검색 탐지는 최근 200개 후보 중 허용 범위 결과.
  사건 상세는 기본 근거 3개이며 페이지 이동. 사건 전체 수와 현재 페이지를 구분한다.
POST /api/detections/preview, /api/detections/{id}/replay
  정책 최대 8단계, 단계당 조건 20개·최소 이벤트 수 1–100. 정책 창 최대 7일.
  replay는 현재 버전과 안정된 요청 ID를 요구하고 늦은 이벤트 대기를 다시 적용하지 않는다.
GET /api/entities/graph
  창 최대 366일, 후보 이벤트 10,000개, 요청 노드 한도 1–500, 간선 1000개.
  간선당 예제 근거 5개. 한도를 넘으면 창을 좁혀야 하며 전체 관계처럼 잘라 표시하지 않는다.
  공통 화면 그래프는 최대 120노드를 그리며 더 많으면 표시 수와 전체 수를 알린다.
POST /api/behavior/baselines, /api/behavior/baselines/{id}/evaluate
  버킷 60–86400초, epoch 경계 정렬, 창 최대 336버킷·366일.
  그룹 10,000개·엔터티 500개·이상 징후 200개 한도. 평가 창은 학습 창 이후다.
POST/PUT /api/playbooks, POST /api/playbooks/{id}/runs
  정의 64KiB, 순차 동작 1–16개, 단계 재시도 1–5회.
  실행 목록은 최근 권한 범위 내 최대 100개. 승인 없이 자동 실행하지 않는다.
POST /api/content/packages, .../test, .../publish, .../rollback
  단일 고정 인덱스, 규칙 20개·소스 범주 8개·테스트 2–12개.
  테스트당 이벤트 100개, 전체 400개·1MiB. 테넌트 100패키지·각 30리비전.
  라이브 필드 확인은 최근 24시간의 존재 확인이다.
PUT /api/parsers/{name}, GET /api/quarantine, POST /api/quarantine/replay
  매핑 32개·raw 경로 깊이 5, 마스킹·필수 필드 각 32개.
  격리 테넌트당 1000개·32MiB, 목록 API 페이지 1–20개, 재처리 요청 최대 100개.
POST/PUT /api/source-monitors
  정확한 인덱스 1–16개·필수 필드 최대 16개. 운영 상태를 명시적으로 평가한다.
POST/PUT /api/dashboards
  패널 1–12개·전체 정의 128KiB. 공유 표시는 다른 계정의 수정 권한을 자동 부여하지 않는다.
PUT /api/lookups/{name}
  표당 10,000행·20열·2MiB, 테넌트당 100개. 현재 버전과 미래 만료를 확인한다.
GET /api/xdr/telemetry, /api/xdr/process-tree
  조회 창 최대 366일, 이벤트 목록 반환 1–500개.
  프로세스 투영 후보 5000이벤트·1000노드·출력 2MiB. 한도 초과 시 조회 창을 좁힌다.

권한·승인·브라우저 보호
----------------------
서버가 현재 계정, 테넌트, 역할과 정확한 인덱스 권한을 적용한다. 사건 근거 전체,
조회·비동기 작업, 예약 검색과 실행 승인도 해당 범위를 사용한다. 인덱스 권한
변경은 기존 세션을 폐기한다. 분석가의 읽기와 관리자의 변경 권한을 구분한다.
파서 조회·미리보기·저장과 격리 재처리에는 테넌트 전체 인덱스 권한이 필요하다.
장비·민감 운영 관리는 default 테넌트의 전체 범위 관리자 조건이 별도로 적용된다.

요청 변조 방지를 위해 변경 요청에 CSRF 검증을 사용한다. 서버 CSP는 자체 출처의
스크립트·스타일·연결만 허용하고 iframe 포함, base 변경과 외부 form 제출을 차단한다.
inline script·eval·inline style 허용을 추가하지 않았다. 로그아웃과 화면 이동 시
현재 화면의 요청·이벤트 핸들러·다이얼로그·반복 갱신을 정리한다. CSP나 UI의 버튼
비활성화가 서버의 권한·입력 검증을 대신하지 않는다.

검증과 남은 제한
----------------
0.4 소스의 별도 pytest 회귀 결과: 621개 통과, 실패·오류·skip 0개.
검색 폼과 결과 변환의 의존성 없는 Node 검사 14개, 참조표 셀 보존 검사 8개 통과.
이 검사는 합성 자료를 사용하며 운영 계정·이벤트를 사용하지 않는다. DOM 모형 검사는
실제 브라우저의 배치·접근성 검사를 대체하지 않는다. 실제 적용 상태와 최종 브라우저
검증은 최종 배포 보고서를 기준으로 확인한다.

# xSERA 0.15.0 웹 콘솔 기능 점검

웹 콘솔의 **관리 → AI 학습 자료**에서 CPU 모델용 자료를 추가·편집·제거하고, 샘플과 원본 참조를 관리할 수 있다. **탐지 및 대응 → 탐지 · 연결 분석**에서 모델 평가와 활성화 검토, 단일·복합 탐지 정의 작성과 독립 검토를 진행한다.

## 기본 제공 콘텐츠와 설치 상태

| 콘텐츠 | 제공 수 | 설치 직후 상태 |
|---|---:|---|
| 탐지 라이브러리 | 962개 | 필요한 항목을 선택해 비활성 정책으로 가져오기 |
| 기존 일반 탐지 시작 예제 | 3개 | 기존 탐지 정책 작성 시 선택 |
| AI 복합 탐지 시작 예제 | 8개: 단일 6개, 복합 2개 | 정의 미리보기 후 저장·독립 검토 |
| 정상 분포 학습 예제 | 정상 샘플 24개 / 로그 24개 | 가져오기 전에는 저장된 자료가 아님 |
| 행동 순서 학습 예제 | 시퀀스 96개 / 로그 1,152개 | 가져오기 전에는 저장된 자료가 아님 |
| 행동 순서 연구 예제 | 시퀀스 1,536개 / 로그 18,432개 | 가져오기 전에는 저장된 자료가 아님 |

탐지 시작 콘텐츠는 총 973개 항목이다. 이 숫자는 활성 정책이나 검증된 공격 탐지율을 의미하지 않는다. 새 설치에는 활성 정책과 학습 모델, 저장된 학습 자료가 없다. 관리자가 환경에 맞는 인덱스와 정의를 선택해 검토해야 한다. 기존 라이브러리는 테넌트 정책 한도(200개) 안에서 필요한 항목을 가져온다.

학습 예제 세 팩에는 1,656개 샘플 항목이 있다. 연구 팩은 변형 시나리오를 포함하며 96개 예제 팩과 생성 계열이 겹친다. 1,656개의 서로 다른 실제 공격 기법이나 현장 검증 자료를 제공한다는 의미가 아니다. 정상 분포 팩은 학습 16개와 별도 정상 검증 8개, 순서 팩은 각각 학습/분류 기준/별도 평가 64/16/16개 및 1,024/256/256개로 나뉜다.

## 학습 자료 준비와 모델 연결

1. **AI 학습 자료 → 자료 추가**에서 용도, 이름, 설명과 정확한 원본 인덱스를 입력한다. 정상 분포 또는 시간 순서 분류 중 용도를 선택한다.
2. **샘플 추가**에서 인증된 로그 검색으로 원본을 선택하고 정상/공격 분류, 시나리오 유형, 호스트 묶음, 학습/분류 기준/별도 평가 용도를 지정한다. 시간 순서 자료는 동일 호스트의 원본 2–32개를 순서대로 참조한다. 정상 분포 자료는 검토한 정상 원본 한 개를 참조한다. 분류값은 모델 입력 로그에 삽입되지 않는다.
3. 기본 예제는 **예제 가져오기**로 편집 가능한 초안을 저장한다. 가져오기만으로 로그 수집이나 모델 활성화가 이루어지지 않는다. 관리자가 `ml_synthetic_`으로 시작하는 시험 인덱스를 지정하고 **예제의 테스트 로그 저장**을 실행하면 등록 소스의 실제 수집·수락 경로로 가상 로그를 저장한다. 작업은 작은 묶음으로 진행하고 중단할 수 있다. 중단 전에 수락된 원본은 보존된다.
4. **현재 원본 · 자료 분리 검증**으로 원본 존재, 현재 권한, 수집 출처, 원본 중복과 분리 조건을 확인한다. 시간 순서 모델에는 최소 32개 학습, 16개 분류 기준, 16개 별도 평가 시퀀스가 필요하며 각 집합에 정상/공격 표본이 있어야 한다. 호스트·시나리오 유형·원본 및 발생 시각이 집합 간에 분리되어야 한다. 정상 분포 모델에는 최소 16개 정상 학습 원본과 8개 별도 정상 검증 원본이 필요하다.
5. **CPU 모델 학습**은 현재 자료의 개정 번호와 내용을 고정해 후보 모델을 만든다. **CPU 모델 · 평가**에서 평가 결과를 확인하고 작성자와 다른 분석가가 활성화를 검토한다. CPU 실행이 불가능하면 호환 상태에 **시스템에서 호환되지 않음**이 표시된다.
6. **탐지 · 연결 분석 → 단일 탐지 만들기 / 복합 탐지 만들기**에서 시작 예제를 선택하고 정의를 미리 본다. 복합 정의에는 승인된 활성 모델과 현재 승인된 단일 탐지 정책을 연결한다. 저장한 정의는 독립 검토 후 운영 탐지에 사용한다. 탐지 결과, 연결 분석과 Case는 기존 화면에서 확인한다.

시험 인덱스 이름만으로 기존 규칙과 완전히 격리되지는 않는다. 모든 인덱스를 검색하는 기존 정책은 가상 로그에서 Signal 또는 Case를 만들 수 있으므로, 기본 예제 로그 저장은 별도의 시험 환경에서 진행한다. 이 기능 자체는 실제 호스트 차단을 실행하지 않는다.

## 편집, 제거와 권한

자료 또는 샘플의 변경마다 새로운 개정이 저장된다. 충돌한 화면의 저장은 거부되므로 새로고침 후 변경한다. **개정 이력**과 학습에 사용한 개정을 확인할 수 있다. 이미 학습한 모델은 뒤의 편집으로 바뀌지 않는다.

자료 제거는 삭제 상태와 감사 기록을 남기고 해당 자료가 가진 원본 참조만 해제한다. 원본 로그, 기존 모델과 모델이 보존하는 학습 근거, Case 근거는 지우지 않는다. 사용 모델이 있는지 화면에서 확인할 수 있다. 삭제 상태의 자료를 다시 학습하거나 편집할 수 없으며, 필요한 경우 새 자료를 만든다.

| 작업 | 조회자 | 분석가 | 관리자 |
|---|---|---|---|
| 제공 예제·저장 자료·샘플·이력 조회 | 가능 | 가능 | 가능 |
| 자료 및 샘플 추가·편집·제거 | — | 가능 | 가능 |
| 자료 검증·CPU 모델 학습 | — | 가능 | 가능 |
| 예제 가상 로그를 등록 소스로 저장 | — | — | 가능 |
| 모델·탐지 정의 독립 검토 | — | 별도 작성자 조건 | 별도 작성자 조건 |

모든 작업에는 현재 테넌트와 자료 전체 인덱스에 대한 권한이 적용된다. 일부 인덱스만 읽을 수 있는 사용자에게는 해당 자료가 노출되지 않는다. 모델 활성화와 실행에서도 현재 원본·출처 권한을 다시 확인한다.

## 콘솔에서 사용할 수 있는 주요 기능

대시보드와 로그 검색, Case 조사·증거 보존·분할·병합, 자산 및 엔드포인트 조회, 탐지 정책·라이브러리·단일 및 복합 정의, CPU 모델과 AI 학습 자료, 행동 분석, 플레이북 및 승인 대응, 수집 소스와 수집 품질, 위협 목록, 콘텐츠 배포·되돌리기, 보존·백업, 플랫폼 상태, 계정·접근 권한과 감사 이력을 제공한다. 실제 장비 대응 범위는 연결된 센서 및 공급자와 정책 구성에 따라 달라진다.

이번 기능 점검은 웹 콘솔과 관리 API 연결에 대한 것이다. 이전 0.14.0의 전체 탐지 처리 지연 측정이나 물리 장비 차단 검증을 대체하지 않는다.

VATEX 분석 콘솔 운영 안내
========================

이 콘솔은 실제로 저장된 이벤트, 탐지 근거, 정책과 실행 기록을 표시한다. 데이터가
없으면 빈 상태를 표시한다. 관측 관계, 테스트 통과, 플레이북 완료를 공격 확정이나
호스트 격리 성공으로 해석하면 안 된다. 모든 변경은 사용자가 저장 또는 실행 버튼을
눌러야 요청된다. 폼을 열거나 템플릿을 선택하는 동작은 저장하지 않는다.

계정과 접근 범위
---------------
서버가 현재 로그인 계정의 테넌트, 역할과 인덱스 권한을 다시 확인한다. 화면에
예전에 보였던 자료도 권한이 바뀌면 조회와 실행이 거부될 수 있다. 권한 오류를
회피하기 위해 다른 인덱스 이름이나 케이스 식별자를 입력하지 않는다.

케이스 조회와 저장 검색 탐지 조회는 읽기 역할에서도 가능하다. 케이스 변경,
상관 정책, 플레이북, 콘텐츠 테스트와 소스 모니터는 분석가 또는 관리자 권한을
사용한다. 콘텐츠 게시·롤백, 파서 저장과 격리 재처리는 관리자 작업이다.
파서 조회·미리보기·저장과 격리 재처리에는 테넌트 전체 인덱스 접근 권한이 필요하다.
격리 조회에는 현재 계정의 인덱스 권한이 적용된다.
다른 사용자가 만든 공유 대시보드는 서버가 허용한 소유자 또는 관리자가 수정한다.

로그 탐색과 대시보드
------------------
시각적 검색에서 텍스트, 이벤트 필드와 최대 20개 비교 조건을 지정한다. 조건은 AND로 결합된다.
값 유형을 '숫자'로 선택하면 raw 필드를 숫자로 비교한다. '문자'로 선택한 001과
숫자 1은 같은 입력이 아니다. 문자열 대소 비교는 숫자 비교와 다른 결과를 낼 수 있다.

분석 방식에서 이벤트 상세, 전체 건수, 지정된 필드별 건수를 고른다. 직접 지정할
그룹 필드는 최대 3개이며 쉼표로 구분한다. 결과 필드와 정렬 메뉴에서 투영 필드,
정렬 기준과 방향을 편집한다. 검색 결과 한도는 1–1000개다. 결과 한도에 도달하면
추가 결과가 있을 수 있다. 집계 건수와 화면에 표시된 행 개수는 서로 다른 값이다.

SPL 탭은 서버가 지원하는 명시적인 SPL 부분집합을 사용한다. 탭을 바꾸면 선택한
방식의 조건을 사용하며, 복잡한 SPL을 시각적 조건으로 자동 변환하지 않는다.
저장된 JSON 검색의 숫자 유형, 여러 그룹 필드, 결과 필드와 정렬 설정은 편집할 때
유지된다. 대시보드 패널 검색은 화면의 조회 기간을 적용한다.

대시보드는 최대 12개 패널, 전체 정의 128KiB다. 막대 차트는 count 열을 표시하고,
숫자 패널은 첫 결과의 count 또는 첫 열을 표시한다. 표 패널은 실제 반환 열을
사용한다. 패널 조회 오류를 데이터 0건으로 취급하지 않는다.

케이스 조사
----------
케이스 목록은 근거 전체에 접근할 수 있는 케이스 중 최근 수정순 최대 200개다.
목록의 신규·분석 중·해결 수치는 표시 목록 기준이다. 심각도는 서버가 제공한
최근 탐지 근거에서 가져오며, 값이 제공되지 않은 케이스는 미분류로 표시한다.
목록 필터가 테넌트 전체 통계를 뜻하지 않는다.

케이스를 열면 개요, 타임라인, 근거 그래프, 작업, 실행 기록 탭을 사용할 수 있다.
타임라인과 그래프는 현재 탐지 근거 페이지에 한정된다. 이전·다음 버튼으로 저장된
근거 페이지를 이동한다. 그래프 선은 엔터티, 탐지 정책과 저장 이벤트의 근거 관계다.
네트워크 연결, 프로세스 부모 관계나 인과관계를 추론하지 않는다. 노드를 클릭하거나
키보드로 선택하면 저장된 실제 근거를 확인한다.

상태·담당자 변경에는 변경 사유가 필요하다. 우선순위, 마감, 태그, 분석 메모와
이벤트 북마크를 별도로 기록할 수 있다. 필수 작업이 남아 있으면 해결 또는 오탐
상태로 종료할 수 없다. 북마크에는 실제로 저장되어 있고 권한이 있는 이벤트만
추가한다. 케이스 내보내기는 서버가 제공한 한도 내 자료를 다운로드한다.

저장 검색 탐지 결과는 별도 목록 탭이다. 최신 200개 후보 중 접근 가능한 결과를
표시하며, 저장된 샘플은 최대 10개다. 상태와 담당 값을 버전 확인 후 변경한다.
저장 검색 탐지 결과와 상관 분석 케이스를 같은 결과로 합산하지 않는다.

상관 정책
---------
템플릿 또는 새 정책에서 엔터티 필드, 시간 범위, 실행 간격, 늦은 이벤트 대기,
중복 알림 대기, 심각도, 위험 기여도와 MITRE 기법을 지정한다. 단계마다 검색 조건과
최소 이벤트 수를 편집하고 위·아래 버튼으로 순서를 바꾼다. 최대 8개 단계이며
각 단계는 최대 20개 AND 조건과 최소 이벤트 수 1–100을 지원한다. 같은 엔터티의
서로 다른 이벤트가 시간 순서에 맞아야 한다.

시간 범위 30–604800초, 실행 간격 30–86400초, 늦은 이벤트 대기 0–86400초,
중복 알림 대기 0–604800초다. 실행 간격은 시간 범위보다 클 수 없다.
새 정책과 템플릿 편집은 기본 예약 비활성 상태로 시작한다. 실제 데이터 미리보기는
일치 결과를 보여 주지만 탐지 결과를 저장하지 않는다. 저장 후 활성화 여부를
직접 선택한다.

기존 정책에서 편집기를 열면 새 정책으로 복제한다. 기존 정의를 몰래 덮어쓰지
않는다. 정책 단위의 버전 전환은 콘텐츠 패키지를 사용한다. 과거 구간 재평가는
실제 탐지 결과를 기록하며, 입력한 구간 종료에 늦은 이벤트 대기를 다시 적용하지
않는다. 화면과 서버의 버전이 다르면 새로 고친 뒤 다시 검토한다.

플레이북
--------
왼쪽 동작 팔레트에서 메모, 작업 만들기, 담당자 지정, 상태 변경 또는 승인된
웹훅을 추가한다. 중앙 노드를 선택하여 오른쪽 속성을 편집한다. 위·아래 버튼으로
순서를 바꾸고 삭제할 수 있다. 플레이북은 1–16개 순차 동작을 지원한다.
단계 식별자는 고유해야 한다. 재시도는 최대 시도 1–5회, 기본 대기 1–300초다.

웹훅에는 서버 관리자가 등록한 전송 대상 이름과 고정된 필드 값을 입력한다.
URL 또는 자격 증명을 편집하는 화면이 아니다. 값의 이벤트 변수 치환은 지원하지
않는다. 서버 외부 전송 설정은 기본 비활성이고 별도로 허용한 HTTPS 대상만 쓴다.
가져온 중첩 전송 값은 편집 화면에서 보존하며 같은 이름의 단순 필드로 덮어쓰지 않는다.

정의 저장은 동작을 실행하지 않는다. 케이스 식별자로 실행을 요청하면 승인 대기
기록을 만든다. 요청자와 다른 활성 분석가 또는 관리자가 승인해야 실행된다.
플레이북 정의 작성자와 실행 요청자는 서로 다른 개념이다. 실행 상세에서 승인 범위,
단계 상태, 시도 횟수와 실제 결과를 확인한다. 결과 불명 상태는 운영자가 외부 결과를
확인해야 하며, 완료 표시는 케이스 해결이나 호스트 격리를 뜻하지 않는다.

데이터와 품질
-------------
파서 폼에서 정확한 소스 이름, 선택적 소스 유형, 저장 인덱스, 필드 매핑과 필수
필드를 지정한다. 매핑은 raw 스칼라 경로를 대상으로 하며 최대 깊이 5, 최대 32개다.
메시지 JSON 해석은 선택 기능이고 범용 벤더 파서나 임의 코드 실행이 아니다.

민감 필드 마스킹을 설정할 때 원본 메시지 사본을 함께 확인한다. raw.parsed.password
만 지정해도 원본 message 문자열 속 값은 남을 수 있다. message를 함께 지정하면
원본 메시지 전체를 제거한다. 예제 미리보기는 수집하거나 저장하지 않는다.
처리 실패는 선택한 정책에 따라 격리 또는 수집 거부로 이어진다.

소스 모니터에서 정확한 소스, 1–16개 구체적 인덱스, 필수 필드 최대 16개,
수집 중단과 도착 지연 기준을 정한다. 신규 모니터는 기본 비활성이다. '지금 평가'는
실제 관측값, 누락 필드, 미래 시간과 도착 지연을 측정한다. 정상은 설정한 운영
기준을 만족했다는 뜻이며, 공격 부재나 데이터 완전성을 보증하지 않는다.

격리 목록은 페이지당 10개를 표시한다. 선택 재처리는 현재 정책으로 이미 마스킹된
사본을 다시 검사한다. 제거한 값은 복원할 수 없다. 큐 등록 뒤 인덱싱되기 전까지는
검색에 즉시 나타나지 않는다. 격리 저장소는 테넌트당 최대 1000개, 32MiB 한도다.

콘텐츠 패키지
-------------
패키지 식별자, 제목, 단일 구체적 인덱스, 필수 소스 범주와 필드를 입력한다.
같은 패키지의 인덱스 범위는 리비전 사이에서 변경할 수 없다. 최대 8개 소스 범주,
20개 상관 규칙, 2–12개 예제 테스트를 지원한다. 테스트당 이벤트는 최대 100개,
패키지 전체 최대 400개, 전체 정의 1MiB다. 테넌트당 최대 100개 패키지와
패키지당 최대 30개 리비전이다.

규칙은 상관 정책 폼으로 편집한다. 예제 테스트에는 평가 종료 시간, 구조화된 이벤트와
규칙별 기대 엔터티를 입력한다. 기대 엔터티는 한 줄에 하나다. 음성 테스트는 기대
값을 비운다. 각 규칙에 양성과 음성 테스트가 모두 있어야 한다. 예제는 실제 수집
저장소에 쓰지 않고 같은 분석기로 격리 실행한다. 가져온 배열과 깊은 중첩 이벤트 값은
원본을 보존한다.

권장 순서는 구조·권한 확인 → 불변 리비전 저장 → 저장 리비전 테스트 → 라이브 소스
확인 → 관리자 게시다. 라이브 소스 확인은 최근 24시간 선언한 인덱스와 소스 유형에서
필수 필드가 존재하는 이벤트를 관측했는지 확인한다. 탐지율이나 오탐률 검증은 아니다.
수정한 초안은 먼저 저장해야 테스트와 게시에 사용할 수 있다.

게시와 롤백은 실제 상관 정책을 하나의 트랜잭션으로 전환한다. 현재 활성 리비전이
다르면 전환은 거부된다. 롤백은 과거 활성화 기록이 있는 리비전만 허용한다.
각 규칙의 예약 활성 설정이 그대로 적용되므로 게시 전 상태를 확인한다.
JSON 파일 가져오기는 구조와 권한을 먼저 검사하며 자동 저장하지 않는다. 내보내기는
선택한 저장 리비전이다. 현재 패키지는 순서형 상관 정책 부분집합이며 범용 Sigma
규칙·상관 의미를 자동으로 손실 변환하는 기능은 제공하지 않는다.

회귀 검사
---------
저장 검색과 대시보드 편집기의 핵심 회귀 검사는 의존성 없는 Node 명령으로 실행한다.
저장소 루트에서:

  node tools/check_console_queries.cjs
  node tools/check_console_queries.cjs <결과 JSON 경로>

실제 production JavaScript의 편집기와 결과 변환 함수를 읽어 DOM 모형으로 실행한다.
숫자·문자 유형, 다중 그룹과 정렬 보존, JSON 문자열 입력, 기본 SPL 언어, 숨겨진 폼
유효성 제어, 실제 API 사전형 행, 숫자 패널과 막대 레이블을 검사한다. 이 검사는
브라우저의 배치·접근성 검사를 대체하지 않는다. 운영 이벤트나 계정 자료는 사용하지 않는다.

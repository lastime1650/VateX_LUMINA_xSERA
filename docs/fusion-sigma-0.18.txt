xSERA 0.18.0 — CPU 관계·시간·장기 스케치 융합 / Sigma 가져오기 운영 계약
2026-10-16

1. 실제 탐지 판단

새로 학습한 연구 모델은 24개 기존 관계 특징·7개 행동 클래스를 사용하는 CPU PyTorch
관계 예측과 자체 시간·스케치 계산을 결합한다. 정상 학습 원본으로 기준을 고정하고,
시간 분리 정상 검증에서 성분별 분모와 최종 임계값을 정한다. 실행 로그로 기준을
자동 재학습하지 않는다. 점수는 악성 확률이 아니다.

정규화한 유효 성분을 relation / temporal / sketch라 할 때 최종 점수는
max(각 유효 성분의 최댓값, 0.55 × 유효 성분의 합)이다.
각 결과의 fusion에는 성분별 원점수·정규화 점수·유효 여부·원본 근거·판단 이유가 있고,
run.decision에는 최종 점수·임계값·성분 제거 시의 재판단이 있다. 기존 관계 CE 점수는
진단으로 남는다. 여러 보통 수준의 성분이 합쳐 임계값을 넘거나 하나의 충분히 큰
성분이 단독으로 넘을 수 있다. 전체 성분과 기여 제거 비교를 함께 검토한다.

시간 전이는 인증된 source/device/boot/process incarnation과 충분한 같은 인스턴스의
관측 이력이 있어야 사용한다. 오래 도착한 이벤트·원본 부족에는 해당 성분이 기권한다.
스케치는 128개 고정 버킷과 24시간 반감기를 사용한다. 이 값은 고정된 정상 기준과
현재 원본 창을 비교하는 자체 설계이며 전체 논문의 GNN·산업 성능을 재현한 것은 아니다.
기준 기간은 검토한 정상 학습 원본이며 실행 시 비교 분포는 최근 최대16개 관측이다.
프로세스 생성의 process_create/process_created/process_creation은 새 융합 성분에서
execute로 분류하고 process_observed는 초기 관찰로 유지한다. 기존 CE 입력·클래스의
의미는 구버전 가중치·승인과의 호환성을 위해 보존한다.
창은 신규 원본 최대16개와 검증된 이전 문맥 최대16개이다. 이전 문맥 원본도 증거에
포함하여 복합 탐지가 이를 독립 증거로 중복 계산하지 않게 한다.

모델·학습 원본·실행 원본·소스 버전·현재 소유자/검토자 권한을 다시 확인한 결과만
공통 ML 신호로 공개한다. 공개 시 실제 CPU 관계 재추론과 원본 문맥 재실행으로
융합 성분·판단을 검증한다. 트랜잭션 안에서 계산만 재사용하며 권한은 재검사한다.
공통 신호를 소비하는 분석가도 실행 원본과 모델 전체 인덱스 범위에 대한 현재 권한을
충족해야 한다. 모델 ID를 직접 고정하지 않은 kind:ml 복합 규칙에도 이 검사를 적용한다.
활성 모델의 최근 문맥 원본은 수명주기 정리에서 보호한다. 만료·철회된 이전 문맥은
제외 사유를 남기고 신규 입력을 계속 처리한다. 학습 소스 철회 시 모델 사용은 중지한다.

0.17 기존 승인 모델의 관계 CE 판단·모델 해시·승인을 유지한다. 기존 모델의 설명용
시간·스케치 요약이 소급하여 탐지 권한을 얻지 않는다. 새 융합 사용에는 정상 자료로
신규 학습 → 검증/품질 점검 → 다른 분석가 승인 → live 활성화가 필요하다.

2. Sigma를 기존 JSON 규칙으로 가져오기

콘솔: 탐지 · 연결 분석 → 신호/탐지 정의 → Sigma 가져오기.
API: /api/content/sigma/imports (목록/생성), /{id} (상세/새 개정),
/{id}/convert, /validate, /review, /activate, /retire.
변경·변환·검증·검토·활성화에는 expected_revision을 지정한다.

필요한 설치: sigma-analysis 선택 구성(pySigma 2.0.1, PyYAML 6.0.3).
가져오기 입력은 64KiB 이하의 단일 JSON/YAML 텍스트이다. 브라우저에서 파일을 읽어
같은 본문으로 제출한다. 서버가 임의 URL이나 로컬 경로를 가져오지 않는다.
중복 키, YAML alias/anchor/merge/다중문서/사용자 태그, 과도한 깊이를 거부한다.
전체 pySigma 규칙·상관 규칙·임의 backend/plugin을 지원한다고 해석하지 않는다.
현재 지원하지 않는 modifier·타입·의미는 변환 오류로 표시한다.

입력 순서:
  a. 이름/심각도, 정확한 인덱스, 활성 등록 소스의 ID/버전을 선택한다.
  b. Sigma 필드→event/projection/raw 경로와 logsource 조건을 명시한다.
  c. 선택 소스의 무해한 양성·음성 원본을 각각 하나 이상(총2~32개) 작성한다.
  d. 가져온 초안을 자체 JSON 조건으로 변환한다. pySigma AST의 AND/OR/NOT과
     타입을 직접 보존하고 source ID/version/index 가드를 결합한다.
  e. 실제 native evaluator로 모든 fixture를 검사한다. 검증은 운영 원본·신호를
     만들지 않는다. 양성/음성 중 하나라도 기대값과 다르면 승인할 수 없다.
  f. 작성자·최종 편집자와 다른 현행 분석가/관리자가 검증 해시와 원본을 검토한다.
  g. 같은 개정·소스 계약·검증·승인이 유효할 때 자체 atomic JSON 정책을 활성화한다.
     정책과 가져오기 binding은 하나의 트랜잭션으로 저장한다.

런타임은 기존 JSON 정책 엔진이다. RE2 정규식, 명시 typed scalar 비교, OR/NOT
조건 트리를 사용하며 pySigma/PyYAML의 런타임 설치가 없어도 이미 승인된 정책의
실행 의미를 바꾸지 않는다. 원본/변환 해시·검증·승인·소스 계약은 실행마다 재확인한다.
관리되는 Sigma 정책을 기존 일반 편집/승인 API로 우회 변경할 수 없다.

새 개정 저장은 연결된 활성 자체 정책을 즉시 draft/비활성으로 돌리고 기존 검증과
승인을 지운다. 변환→검증→독립 승인→활성화를 다시 수행해야 한다. source 버전 변경,
작성자/검토자 권한 철회 또는 엔진 의미 변경 때도 재검토가 필요하다. 종료는 이력을
보존한다. 과거 신호를 새 개정으로 소급 승인하지 않는다.

3. 수집·복합 탐지·Case와 운영 범위

관측 신호는 단순 수집 증거이다. 융합 ML과 가져온 atomic 규칙의 탐지 신호는 별개로
표시한다. 기존 복합 탐지의 독립 원본 수·현재 승인·동일 엔터티/시간 조건이 충족되면
composite 신호와 Case를 생성한다. 공유 원본/문맥은 독립 근거로 다시 세지 않는다.
합성/외부 센서 로그는 센서 설치·커널 캡처나 내용의 진실성 인증을 뜻하지 않는다.

CPU 사용을 유지한다. 이 변경이 실제 호스트 격리·프로세스 종료·IP 차단을 승인하지
않는다. 실장비/현장 탐지율/대규모 지속 부하/Yocto 자체 OS 인증은 별도 시험 대상이다.
전체 회귀·시간차 HTTP 시뮬레이션·패키지/이전 버전 호환 결과와 정확한 동결 해시는
이번 작업의 0.18 HTML 검증 보고서에서 확인한다.

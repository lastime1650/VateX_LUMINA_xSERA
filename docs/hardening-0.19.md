# xSERA 0.19.0 운영·탐지 보강

0.18.0의 여섯 개선 항목을 제품 코드와 검증 경로에 반영한다. CPU 실행을 유지하며 이 릴리스 검증에서 실제 호스트 차단을 실행하지 않는다.

| 개선 항목 | 구현 | 운영 전 확인할 증거 |
|---|---|---|
| 모델 일반화와 데이터 품질 | 버전별 CPU 모델, 호스트·시간·행위군 분리 평가, 정밀도·재현율·호스트 일수별 오탐 및 신뢰구간, 원본·라벨 분리 | 합성 시험 수치를 현장 탐지율로 일반화하지 않으며 실제 정상·공격 원본을 같은 평가 경로로 평가 |
| 장기 행위와 모델 수명 | 64개 입력 특성의 별도 v2 모델, 1시간·24시간·7일 원본 기반 비교, 두 해시 스케치와 정확한 패턴 분포, 독립 검토한 재기준 설정·승격·롤백 | 관측 시간 범위·원본 상한·표본 선택·가시성 제외를 확인; 전체 기간 수집을 추정하지 않음 |
| Sigma 호환·배포 | 운영 승인본과 편집 초안 분리, 원자 교체·과거 승인본 롤백, event_count/value_count/temporal/temporal_ordered, 관측 필드 매핑과 실제 판정기 fixture | 지원 목록 밖 문법은 거절. 계수·상관 증거는 원본·부모 각 32개 한계와 초과 상태 확인 |
| 실시간 지연 | 영수증/색인 커밋 후 단계별 generation 통지, 주기 재조회 복구, 제한된 모델 배치와 처리 공정성, 인덱스 권한별 처리 대기·단계 시간 | 주어진 전송률·CPU 작업·코호트에서 손실, 대기열 소진과 지연 측정. 최대 기업 EPS 보증과 구분 |
| 대응·회복 | 독립 승인된 가상 장비 대응, 관리 통신 유지·임대 만료·저장소 재개·해제 검증; 실제 소유 Python 프로세스의 단일 writer/인계/백업 복원 | 실제 장비 OS 방화벽·물리 재부팅·다중 서버 HA는 별도 검증 필요 |
| 운영·수집 범위 | 외부 신뢰키로 검증하는 Ed25519 패키지와 시작/heartbeat 재측정, 수신 영수증·보고 드롭·시퀀스 공백 분리, Entra/M365 원본 수집, 연구→신호→Case 추적 GUI | OS 코드 서명 인증, 실서비스 자격 증명과 권한, 센서 수집 전 손실, 실제 Yocto BSP 부팅은 별도 확인 |

기존 JSON 시나리오 룰과 공통 atomic/composite 룰은 유지한다. Sigma는 승인 후 같은 공통 판정기에 native 조건이나 상관 정의로 배포한다. 새 GUI의 연구 모델 학습은 명시적으로 v2를 선택하며 기존 `/api/research/train` 요청은 `gate_version`이 없으면 v1 계약을 유지한다. 기존 모델·승인·가중치를 자동 변환하지 않는다.

장기 판단의 최근 원본 목록은 기존 32개 계약을 유지한다. 추가 장기 원본은 해시로 고정한 manifest로 연결하고, 복합 탐지의 의존 그룹 계산은 전체 원본 집합을 사용한다. Case 기여가 생성되면 장기 원본까지 영구 증거 참조로 보호한다. `/api/intelligence/signals/{id}/evidence?offset=0&count=32`는 전체 인덱스 권한과 보존 영수증·원본 해시를 확인해 페이지 단위로 반환한다. 모델 비활성화·폐기 뒤 과거 증거 조회는 현재 탐지 권한을 부여하지 않는다.

웹 콘솔의 **운영 검증 · 수집 품질**에서 시험 계획 작성, 별도 관리자 검토, 가상 시험 실행, 결과 열람, 시퀀스·무수신 기준 설정, 기업 원본 등록·가져오기와 기본 탐지 초안 생성을 수행한다. 연구 분석 결과의 추적 화면에서 신호와 Case로 이동한다. 메일 기본 탐지는 전달 대상이 원본에 명시된 설정 변경을 조사 대상으로 분류한다. 합법적인 관리 작업을 악성으로 단정하지 않는다.

**AI 평가 · 기준 갱신** 화면에서 합성 평가 자료 생성, 수집한 원본을 연결한 평가 명세 가져오기, 명세의 정상 분할을 사용한 CPU v2 학습, 테스트 지표·성분 제거 비교, 정상 기준 후보의 준비·독립 검토·승격·롤백을 수행한다. 평가 manifest와 원본 해시는 변경하지 않고 새로운 자료로 교체한다. 모델 교체 후 모델 개정에 고정된 복합 규칙을 다시 검토한다.

완료된 평가 자료와 실행 기록은 생성자와 다른 분석가가 근거를 남겨 보관 처리한다. 보관된 자료는 신규 학습·평가 선택과 활성 자료 한도에서 제외하되 원본 명세·평가 결과·해시 이력을 유지한다. 자료별 원본 참조 해제는 활성·검토 대기 모델, 진행 중 후보, Case, 북마크와 법적 보존 관계를 다시 확인한 뒤 처리한다. 보관 처리는 원본 파일의 즉시 삭제나 다른 모델·Case의 참조 삭제를 수행하지 않는다.

Microsoft 서비스 수집은 읽기 전용 Graph/Management API 요청과 테넌트에 고정한 OAuth 자격 증명을 사용한다. source의 `credential_ref` 환경 변수에 배포 관리자가 테넌트·client ID·client secret을 구성한다. 비밀값은 콘솔에서 입력하거나 반환하지 않는다. Office 수집은 이미 활성화된 감사 구독만 읽는다. 허용한 HTTPS 호스트·경로와 페이지·시간·크기 한계를 적용하며 원본 영수증·체크포인트 커밋 뒤 다음 페이지로 진행한다. 실제 서비스 자격 증명이 없으면 기능을 사용할 수 없다고 표시하며 프로토콜 시험을 실서비스 검증으로 표현하지 않는다.

서명·가상 대응·복구 구성은 [운영 검증 안내](operational-qualification.md)를 따른다. 서명 개인키는 패키지나 API 응답에 포함하지 않고, 신뢰 공개키를 에이전트 외부에 별도로 배포한다. 이 서명을 OS Authenticode 인증으로 표현하지 않는다.

기술 기준: [Microsoft signIn](https://learn.microsoft.com/graph/api/resources/signin?view=graph-rest-1.0), [Microsoft 365 감사 스키마](https://learn.microsoft.com/en-us/office/office-365-management-api/office-365-management-activity-api-schema), [Sigma 상관 규칙 명세](https://sigmahq.io/sigma-specification/specification/sigma-correlation-rules-specification.html). 논문의 아이디어를 적용한 자체 구현이며 논문 전체 재현이나 상용 제품 인증을 주장하지 않는다.

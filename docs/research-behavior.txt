xSERA CPU 행위 연구 기능 운영·검증 가이드
======================================

이 기능은 논문의 설계 아이디어를 xSERA의 CPU·원본 증거·권한 모델에 맞게
직접 구현한 보조 탐지 및 조사 기능이다. 논문 원형 재현, 논문 탐지율 재현,
악성 확률 또는 전체 시스템의 완전한 정보 흐름 복원을 주장하지 않는다.
공개된 논문과 아래 출처를 참고했으며 원저자 코드·가중치·연구전용 데이터는
복사하거나 번들하지 않았다. 실제 호스트 차단 권한을 부여하지 않는다.

1. 실제 학습하는 CPU 모델

24차원 개별 이벤트 특징을 입력으로 받아 7종류의 관측 관계(execute/read/
write/connect/authentication/registry/other)를 예측하는 선형 인코더+작은
신경망이다. PyTorch CPU에서 1~3개의 서로 다른 seed로 실제 학습한다.
기존 GRU 시퀀스 모델과 autoencoder를 대체하거나 같은 모델이라고 표시하지
않는다. 프로세스 이미지·명령행과 파일/레지스트리/주소의 정규화된 토큰을
결정적 8+8개 해시 통계로 요약하고, 명령행 길이·인코딩 명령 옵션·외부 주소·
포트·실행파일 대상 여부·레지스트리 대상 여부·명시적 프로세스/부모 identity
유무를 사용한다. 사건 ID, 호스트 이름, campaign/ground-truth 레이블은
특징에 넣지 않는다. 관측 action은 정답 관계이며 입력 특징에 넣지 않는다.

학습에는 원본 training_ids 16~1024개와 독립된 validation_ids 8~256개가
필요하다. 모든 학습 사건 시간이 모든 검증 사건 시간보다 앞서야 한다.
최소 두 정상 관계 종류가 필요하다. 정상 학습임을 운영자가 확인해야 한다.
검증 손실의 최대값과 고정 여유값으로 임계값을 정하며 공격/테스트 레이블로
임계값을 고르지 않는다. 평가에는 seed별 학습 전후 cross entropy, 검증
관계 정확도, semantic feature 제거 ablation, 단순 관계 빈도 baseline이
포함된다. 이것은 관계 예측 평가이며 실제 공격 precision/recall은 아니다.
공격 precision/recall, 호스트 하루당 오탐 Case 수, Case 지연은 별도 실험
전에는 null로 반환한다.

기본 검토 모드는 shadow이다. 제작자 자신은 활성 승인할 수 없다.
독립된 현재 권한의 운영자가 mode=live를 명시하여 승인하면 이후의 원본
이벤트에 자동 추론한다. 0.18 신규 모델은 아래 명시적 융합 점수가 보정된
최종 임계를 초과해야 live 신호 후보가 된다. 모델·원본·리뷰·권한을 다시 검증하는 공통 intelligence adapter를
통과해야 신호와 복합 탐지에 사용할 수 있다. 한 ML 신호만으로 악성을
확정하거나 호스트 차단을 실행하지 않는다.

live 승인에는 모든 training/validation 원본의 인증된 source admission
receipt가 필수다. source ID/version/owner/definition hash를 원본별로 핀하고
현재 source owner 권한까지 재검증한다. 소스가 철회되거나 소스 소유자의
index 권한이 없어지면 모델이 더 이상 live 부모가 될 수 없다. 일반 JSON
수집으로 들어온 raw.source_id/device/boot 주장은 인증 source receipt로
격상되지 않으며 해당 원본은 shadow 연구에만 사용할 수 있다. live 추론
원본에도 동일한 현재 source 권위가 필요하다.

1a. 0.18 실제 판정을 바꾸는 정상 보정 융합

신규 학습 모델의 snapshot.fusion에는 구현 hash, 고정 정상 baseline,
정상 검증의 보정값, 가중치, 임계값, 보정 원본 ID와 ablation 결과를 넣는다.
독립 리뷰는 이 전체 snapshot digest를 승인한다. 기존 0.17 모델의 원래
feature contract(c42045a942417634024c5510458a59c9c4292d67883e181e105394d45d619b97)
와 CE 판정은 그대로 유지한다. 기존 승인 모델에 융합을 조용히 덧붙이지
않는다. 융합으로 바꾸려면 새 버전을 학습하고 다시 독립 리뷰해야 한다.

정상 학습 원본만 reference를 만든다. 프로세스 이미지별 정상 전이 빈도와
전이별 시간 간격, 이미지 지원량, 128-bin 정상 이력 분포를 고정한다.
분포는 정상 학습의 전체 최대 1024개 원본을 24시간 반감기로 요약한다.
실시간 관측과 경고가 이 정상 기준이나 가중치를 자동 갱신하지 않는다.

세 성분은 relation CE, 같은 process incarnation의 새 전이/희소성/간격
변화, 최근 유효 원본 최대 16개 분포와 고정 정상 이력 사이 total variation
거리다. relation은 정상 검증 CE 임계로, 시간·스케치는 시간 순으로 분리한
정상 검증 최대값+각각 0.15/0.10 여유로 나눈다(최소 0.25/0.10).
각 정규화 성분은 최대 4이며, 자격 없는 시간·스케치는 0으로 기권한다.

final_score = max(max(relation, temporal, sketch),
                  0.55 * (relation + temporal + sketch))
final_threshold = max(1.0, 정상 검증 final_score 최대값 + 0.10)

같은 단위로 보정한 점수의 결정적 결합이며 악성 확률이 아니다. 강한 한
성분 또는 여러 중간 성분이 실제 판정을 바꿀 수 있다. 각 성분 제거 후의
점수와 판정을 모든 run에 기록한다. 정상 검증은 학습 reference에 포함하지
않는다. 합성 정상 검증의 경고 0건은 실제 환경의 오탐률을 뜻하지 않는다.

시간 성분은 같은 인증 source/device/boot/process incarnation에서 먼저
관측한 원본 2개와 이미지 정상 관측 8개 및 정상 전이 7개가 있어야 한다. 스케치는 유효한
원본 8개 이상과 정상 지원 16개가 필요하다. source/boot 등이 없거나 새
incarnation/희소 맥락이면 시간 성분이 기권한다. 실제 수신 순서에서 늦은
원본은 시간·스케치에 기권하고 다음 맥락에도 저장하지 않는다. 관계 CE는
이와 독립적으로 평가한다. 단순 cold start 또는 중복 ID로 시퀀스 지원량을
부풀리지 않는다.

자동 실행은 최대 16개 새 원본과 이전 최대 16개 맥락 원본을 사용하므로
live signal ancestry는 항상 32개 이하다. 맥락 원본도 신호의 원본 집합에
모두 포함하므로 그 원본을 다른 atomic으로 다시 제시해 독립 근거로 셀 수
없다. 맥락 자체의 기존 이상 판정을 다음 run에서 다시 발행하지 않는다.
기존 맥락의 receipt/권위가 사라지면 제외 이유를 기록하고 유효한 새 원본의
처리를 계속한다. 학습 소스 권위 철회는 전체 모델의 권위를 철회한다.

최종 publication 검증은 현재 원본으로 실제 CPU 추론과 융합을 다시 계산해
점수/성분/근거/최종 판정을 비교한다. TX-local memo는 이 순수 계산만
재사용하며 현재 ACL, 모델 리뷰, source 권위와 receipt/hash를 생략하지
않는다. 정상 상세 압축·outbox GC 뒤에도 현재 맥락 원본은 별도 model
reference와 protected_ids로 보호한다. 모델 은퇴 시 해당 맥락 reference만
해제하며 Case와 다른 모델 원본은 해제하지 않는다.

2. 그래프와 시간·장기 분석

- ORTHRUS/HOLMES에서 얻은 조사 관점: 이상 이벤트 주변에서 시간 순서를
  지키는 인과 경로를 최대 8개, 경로당 최대 8개 edge로 축약한다.
  T1059.001/T1547.001/T1003.001/T1021 텍스트 힌트를 제공하되 확인된
  공격 또는 완전한 ATT&CK 탐지로 표시하지 않는다.
- KAIROS에서 얻은 시간 관계 관점: 같은 프로세스 incarnation의 이전 action,
  시간 간격, 제한된 전이 빈도와 새 전이 여부를 계산한다. 자체 CPU 통계
  변형이며 원 논문의 TGN/GNN을 재현한 것이 아니다.
- UNICORN에서 얻은 장기 요약 관점: 128개 고정 bin의 그래프 특징 스케치와
  24시간 반감기의 감쇠를 유지한다. 프로세스/전이 상태도 각 128개 이하다.
  스케치는 원본과 같은 자료가 아니며 원본 이력을 다시 구성할 수 없다.
  늦게 도착한 사건은 현재 시간 상태를 되돌리지 않는다.
- NodLink에서 얻은 작은 온라인 조사 그래프 관점: 별도로 직접 작성한
  유계 greedy 선행 경로를 제공한다. Steiner-tree 근사 보장이나 NodLink
  구현 재현을 주장하지 않는다. 원저자 라이선스는 Research-Only MIT이며
  상업 사용을 금지하므로 해당 코드와 데이터는 포함하지 않는다.

한 실행에는 원본 최대 32개, 노드/edge는 각각 최대 128개다. 프로세스 간
연결에는 source/device/boot/GUID/start identity가 필요하다. PID 또는
같은 호스트라는 이유만으로 연결하지 않는다. 파일 경로만 일치하면 버전이
같다고 보지 않으며, 소스·device·boot·파일 SHA256이 없으면 이벤트별
별도 대상으로 취급한다. 네트워크 장비 로그만으로 호스트 내부 동작을
복원하지 않는다. 관계와 TTP는 admitted telemetry의 보고 내용을 설명한다.

3. Windows PRISM 아이디어의 보수적 적용

서비스 IPC 후보, 2초 단위 서비스 실행 구획, UUID/SID/hash 등의 불확정
경로 토큰 그룹화, 읽기 전용 leaf 데이터의 설명용 그룹화를 구현한다.
서비스 이름이나 C:/Windows 경로는 무결성 증명이 아니므로 해당 이유로
이벤트·탐지·경고를 삭제하거나 억제하지 않는다. 그룹에 속한 원본 ID와
실제 경로를 보존하며 Registry 쓰기·지속성 신호를 읽기 잡음으로 합치지
않는다. Doc2Vec 학습 또는 저자 80개 서비스 필터 목록 재현은 아니다.

4. 데이터 품질과 보존

학습/검증/테스트의 중복 사건, 동등 특징·관계 패턴, 시간 겹침, 호스트 겹침,
campaign 겹침, 반복 배경 비중, 레이블 필드 유무를 평가한다. 평가 레이블은
보고서에만 사용하며 탐지 모델에는 넣지 않는다. campaign 주석이 없으면
campaign 분리 성능을 알 수 없다고 표시한다. 합성 시나리오 개수는 실제
환경의 탐지율 근거가 아니다. 동일 정상 행위가 검증에 다시 나오는 것은
가능하므로 내용 겹침은 경고하고, 사건 ID 중복과 역전된 시간 분리는 차단한다.

정상/shadow 상세는 최근 128개 또는 24시간을 지나면 bounded lifecycle이
특징과 상세 그래프를 compact한다. 영구 run ID, 원본 admission/record hash,
숫자 판정, 원 payload/graph hash와 archive 원장을 유지한다. 해당 일반
run reference만 해제하며 Case/법적 hold/live anomaly/다른 모델과 데이터셋/
대기 작업의 원본 보호는 유지한다. 원본 로그를 직접 물리 삭제하지 않는다.
live anomaly와 Case 원본 또는 tenant legal hold가 있는 run은 상세 보존한다.
전체 run 행 수가 2000개를 넘었다는 이유로 자동 추론을 중단하지 않는다.

활성 모델은 tenant당 최대 8개, 비은퇴 모델은 최대 64개다. 모델 은퇴는
비활성화 후 독립된 운영자가 명시적으로 수행하고, 미처리 원본이 있으면
거부한다. 모델 가중치·출처·은퇴 원장은 보존하며 해당 모델 학습 reference만
해제한다. 은퇴 모델은 다시 활성화하거나 추론할 수 없다. 새 버전 학습을
통해 운영 후보를 다시 만든다.

viewer는 현재 scope의 상태·기록·품질만 확인할 수 있다. 학습·분석·리뷰·
보존 변경에는 analyst/admin이 필요하고, 모든 작업은 tenant와 현재 index

GPU를 요구하지 않는다. CPU framework가 없으면 '시스템에서 호환되지 않음'
상태로 반환하며 점수 또는 성공을 꾸미지 않고 다른 분석을 계속한다.

검증 제한

컴포넌트 시험은 무해한 합성 원본과 실제 CPU 학습/추론을 사용한다. seed별
수치와 ablation은 해당 fixture에 대한 결과이며 국제 논문이나 상용 XDR과의
탐지율 동등성을 뜻하지 않는다. 실제 업무 정상 배경, 장기 계절성, 서로
다른 소스·호스트·공격 캠페인과 누락/지연을 포함한 검증을 추가해야 한다.
운영 data 폴더를 학습 목적으로 자동 탐색하거나 운영 장치에 명령을 보내지
않으며, 승인된 명시적 원본과 별도 시험 저장소만 사용한다.

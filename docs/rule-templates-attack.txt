XDR 시작 템플릿과 ATT&CK 참조 — 0.6

사용자가 제공한 XDR_V2 원본은 변경하지 않았다. examples/endpoint_rules_100.json,
endpoint_rules_additional_200.json, endpoint_rules_expansion_600.json,
examples/test_agent/rules_lab_50.json을 출처·SHA256와 함께 catalogs/에 복사했다.
각 100/200/600/50개, 총 950개 고유 ID이다. 원본 활성 설정은 547개 true,
403개 false이지만 이 제품의 라이브러리는 모두 비활성이다. 원본 생성기는
실행하지 않았으며 해시만 기록했다. 동일 ID와 동일 구조의 룰 중복은 없었다.
이 결과가 950개 독립적인 공격 탐지 효과를 입증하지는 않는다.
원본 생성기는 ready 플래그로 사용자 모드 수집기에서 기대되는 자료와 별도
Sysmon/커널/audit 센서가 필요한 자료를 구분해 일부 룰을 끈다. 목록에
source_default_enabled와 telemetry_verified:false를 제공하며 원본 비활성 룰은
별도 센서/필드 준비 경고도 표시한다. 템플릿 가져오기가 센서를 설치하거나
547개 자료원의 실제 설치 상태를 검증하는 것은 아니다.

920개 임계값 룰과 30개 순차 행위 룰은 endpoint-string-re2-v1 변환 프로필로
준비할 수 있다. supported:true는 이 프로필에서 실행 가능한 정책을 만들 수
있다는 뜻이며 원본 엔진과 동등한 의미, 운영 검증 또는 ATT&CK 전체 탐지
커버리지를 뜻하지 않는다. 응답의 support_level은 adapted,
source_semantics_equal은 false이다. 가져오기에는 accept_adaptation:true와
한 개의 정확한 논리 인덱스가 필요하며 생성된 정책은 항상 enabled:false다.
기존 정책 검토·미리보기·버전 기반 활성 API를 거쳐 운영자가 켜야 한다.
테넌트당 기존 총 정책 한도 200개(활성·비활성 포함)는 그대로 유지되어 950개 일괄 활성화하지 않는다.

변환은 aegis.endpoint.v1의 중첩 raw.xdr.data만 대상으로 한다. source schema,
sourcetype, 지정 인덱스 조건을 각 단계에 붙이고 host.id를 검증된 최상위 host로
그룹화한다. JSON 문자열·숫자·누락/null을 구분한다. eq 숫자는 typed_eq,
목록 포함은 typed_in, 존재 여부는 exists, 숫자 비교는 number_* 연산자를 쓴다.
raw 필드 경로는 최대 8단계다. SQL은 서버 컴파일러가 만들고 모든 값은 바인딩한다.
일반 문자열 contains와 typed 문자열 연산을 혼동하지 말아야 한다.
숫자 비교는 DOUBLE을 사용하며 typed 숫자 상수는 ±(2^53-1) 이내로 제한한다.
이 기능은 임의 정밀도 수학 엔진을 제공하지 않는다.

대소문자 무시 문자열은 DuckDB RE2의 단순 Unicode folding으로 평가한다.
원본 Python casefold의 다문자 변환(예: ß→ss)과 다를 수 있다. 문자열 조건은
JSON 스칼라 문자열에 적용하므로 원본의 list-valued contains는 재현하지 않는다.
정규식은 1..1024자, 제한된 문법만 허용하며 lookaround, backreference,
문자 클래스, 중괄호 수량, 사용자 정의 inline group을 거부한다. 원본 wildcard의
*와 ?는 명시적으로 변환하지만 대괄호 문자 클래스는 지원하지 않는다.
향후 임의 입력의 미지원 연산/OR/NOT/중첩 조건 트리는 오류로 거부한다.

30개 실험실 행위 룰은 모두 단순 AND 조건 두 단계이며 후속 within_seconds120을
보존한다. 예 R-LAB-001은 지정 실험실 호스트의 powershell.exe process_created
이후 120초 이내 defender_detection이다. 원본의 고정 TEST-EDR 호스트 조건을
그대로 보존하므로 실제 배포 호스트에서 자동으로 발화한다고 주장하지 않는다.
시간 간격은 앞 단계 이벤트 시각부터 뒤 단계까지 0..within_seconds 양 끝 포함,
정책 전체 window 안의 서로 다른 이벤트로 평가한다. 이전 시작점이 만료되면
나중 시작점도 검사한다. 시간 제약 체인은 단계마다 min_count1만 허용한다.
최대 10000 후보 방문, 실행 기한·취소, 기존 단계당 1000 미만 이벤트 제한을
적용하고 한도 초과 시 전체 평가를 실패시킨다. 부분 체인/점수를 정상 결과로
반환하지 않는다. 호스트/평가 창당 첫 완전 체인만 만든다. 원본 streaming
max_candidates_per_scope/상태 만료/알림 수와 동일하다는 주장은 하지 않는다.

ATT&CK는 사용자 제공 enterprise-v19.2.json의 858개 기술·하위 기술,
15개 전술이다. MITRE 라이선스와 저작권 고지를 원문으로 포함했다.
provenance.json의 로컬 파일 해시와 catalog의 원본 STIX source_sha256는 서로
다른 대상의 해시다. 전자는 포함한 변환 파일, 후자는 원래 STIX 배포 파일이다.
확인된 공식 자료(2026-10-08):
[ATT&CK data](https://attack.mitre.org/resources/attack-data-and-tools/),
[versions](https://attack.mitre.org/resources/versions/),
[official license](https://raw.githubusercontent.com/mitre-attack/attack-stix-data/master/LICENSE.txt).
XDR 룰 자체에는 별도 공개 라이선스를 확인하지 못했다. 사용자 제공 자료의
허가된 로컬 통합이며 MITRE 라이선스가 XDR 룰에 적용된다고 주장하지 않는다.

950개 룰의 모든 MITRE ID가 포함한 참조에 존재하지만 일부 태그는 deprecated
또는 revoked이다. 원본 태그를 다른 기술로 추측 교체하지 않고 역사적 태그
경고를 표시한다. 기본 catalog 목록은 비활성 기술을 제외한다. include_inactive=true로
858개 전체를 조회할 수 있다. MITRE의 기술 목록은 기술 자체의 심각도나 위협
확률을 제공하지 않는다.

인증된 API:
GET /api/attack/catalog?search=&tactic=TA0002&platform=Windows&offset=0&limit=100
  limit1..200. tactics는 id/name/shortname/url/order, techniques는
  id/name/url/tactics(전술 ID)/platforms/parent/is_subtechnique/deprecated/revoked.
GET /api/attack/techniques/{id}: 기술 설명과 전략·구성요소 참조.
GET /api/rule-templates/summary: 총수/지원수/출처·라이선스·해시.
GET /api/rule-templates?search=&platform=windows&supported=true&offset=0&limit=50
  limit1..100. items/total/offset/limit. search는 ID·이름·MITRE ID를 검색한다.
GET /api/rule-templates/{id}: 원본과 policy_preview, 변환 경고.
POST /api/rule-templates/{id}/apply {"index":"endpoint","accept_adaptation":true}
  관리자/분석가, CSRF와 현재 인덱스 권한 필요. 201 {id,template_id,enabled:false,...}.
  다른 인덱스·폐기된 권한은 거부한다. 중복 명시적 가져오기는 별도 정책을 만든다.

GET /api/incidents/{id}/attack-context는 casework의 전체 허가된 case export를
읽는다. 케이스 조회/기여 전체 인덱스/비공개 북마크 접근 검사를 재사용하며
테넌트와 현재 ACL이 맞지 않으면 케이스를 반환하지 않는다. export의 자료형당
10000행 및 전체2MiB 한도, 응답2MiB 한도 초과 시 오류로 실패한다.
페이지별 기여 결과나 브라우저 필터로 점수를 계산하지 않는다.

점수 정의 case-evidence-max-v1:
  threat_score = min(100, max(0, 전체 기여의 configured weight 최대값))
  severity = 전체 기여 evidence.severity 중 유효한 값의 최대 등급
  기술별 score/severity도 해당 기술을 명시한 기여에 같은 공식을 적용한다.
  기여가 없으면 점수0, severity unknown이다. 반복 증거가 점수를 더하지 않는다.
  점수는 설정된 정책 증거 우선순위이며 MITRE 등급·ML 확률·위험 예측이 아니다.
  기본 템플릿 설정값 info5/low15/medium40/high70/critical90은 운영자가 변경할
  수 있는 정책 값이다. 북마크·메모로 새로운 공격 점수를 만들어내지 않는다.
응답에는 공식 기술 정보, 기여/정책/원본 이벤트 ID, 고유 이벤트 수, 실제 host
entity, 수식과 경고를 포함한다. 알 수 없는 기술은 known:false/url:null로
보존하고 공식 정보처럼 꾸미지 않는다. 이 기능이 격리·원격 명령을 실행하지 않는다.

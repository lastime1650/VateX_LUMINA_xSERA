# xSERA 0.14 CPU 행동 시퀀스와 검증

PyTorch CPU 전용의 단방향 GRU(은닉 24, 1층)는 `[batch,time,55]` 입력과 길이 마스크를 사용한다. 실제 시계열에서 명시된 출처, 호스트·장치·부팅·사용자·세션·컨테이너·namespace 경계로 12개 로그를 모은다. 5초 유휴 후 3개 이상의 부분 창은 길이를 표시해 분석하며 더 짧은 창은 제외 이유를 기록한다. 보고된 식별자는 native 센서 인증이나 인과관계의 증명이 아니다.

원본, 현행 출처 버전, 모델 digest/revision, 검토자 권한과 전체 인덱스 범위를 추론 전후 다시 확인한다. 승인을 취소하거나 모델을 바꾸면 이전 작업을 제외한다. 대기·실행·아직 읽지 않은 outbox·버퍼 원본은 보존 정리에서 보호한다. 모델 출력은 조정되지 않은 점수와 행동 가설이며 직접 차단을 승인하지 않는다. 독립 승인한 정확한 모델 버전에 결합된 복합 정책만 Case 기여를 만들 수 있다.

모델의 원문 JSON·digest와 ID·tenant·버전·범위가 완전히 같은 경우에만 해시 검증한 불변 내용을 프로세스 메모리에서 재사용한다. LRU는 최대 16개·직렬화 원문 32MiB이며, 해석한 Python 객체에는 별도 메모리 비용이 있다. 권한·출처·승인·폐기·원본 receipt의 검증 결과는 저장하지 않고 매번 현행 상태를 다시 확인한다. 새 모델 변경이나 원문 변조는 이전 내용을 재사용하지 않으며 해시 불일치는 사용을 거부한다. 기존 쓰기 트랜잭션 메모의 연결·트랜잭션 경계도 그대로 유지한다. 이는 권한 캐시가 아니라 반복 JSON 해석·직렬화 비용을 줄이는 보완이다.

`python -m tools.sequence_scenarios --help`로 합성 데이터 생성 옵션을 확인한다. 기본 1,536개는 6개 전이 원형 × 4개 패밀리 × 64개 변형, 각 12개 원본이다. 학습 1,024개, 보정 256개, 홀드아웃 256개는 패밀리·호스트·원본·시간 범위를 분리한다. 정상/공격 쌍은 같은 관측 집합과 첫·마지막 관측을 가지며 중간 순서만 다르다. 라벨, 시나리오/패밀리 식별자는 모델 특징에 들어가지 않는다. 홀드아웃으로 문턱값을 조정하지 않는다. 순서를 제거한 비교와 순서 뒤집기 민감도는 평가 결과에 함께 보관한다.

`python -m tools.sequence_lab --work-base <임시시험폴더> --output <결과.json>`은 인증한 loopback HTTPS 임시 서버를 열어 원본을 수집하고 모델을 학습·독립 평가·승인한다. 256개 홀드아웃 창을 새 원본 식별자로 개별 전송해 누적 분석, ML, FortiGate/Cisco ASA와 복합 탐지, Case, 가상 대응 승인·실행·상태 확인·해제, 동결 Shadow 재실행과 ML 보존을 검증한다. 이는 동일 홀드아웃의 실시간 재생이며 두 번째 독립 정확도 평가가 아니다. 임시 저장소만 사용하며 실제 OS/방화벽 효과를 실행하지 않는다.

실시간 원본 작업에는 회차당 최대 1초의 별도 시간 배분을 사용하고, 복합 탐지·기존 탐지·관계 분석의 0.25초 배분은 유지한다. 매 원본의 현행 권한·출처·receipt와 3초 트랜잭션 제한, 최대 32개 회차 상한·취소 검사를 유지한다. 검사 도구는 작은 내부 건수 조회로 완료를 관측한 뒤 권한을 확인하는 API에서 증거를 한 번 가져와 모든 복합 신호의 원본·부모·인덱스가 Case 기여와 일치하는지 검증한다. 내부 건수는 판단이나 대응을 승인하지 않는다. 단계별 완료 관측의 기본 상한은 600초이며 `--stage-timeout`으로 명시한다. 이전 300초 상한 실패와 처리 지연을 보존하며, 상한 연장을 성능 향상이나 운영 SLA로 해석하지 않는다. 실제 서버 시각 기반 지연과 최종 대기열 0건을 별도로 기록한다.

정상/Shadow의 상세 결과는 24시간 또는 모델당 128개 이후 digest·모델 버전·실행 요약을 남기고 압축 보관한다. 정상 실행의 참조만 해제하며 이상 신호·Case·hold·다른 모델·대기 작업 증거는 유지한다. 비활성 모델은 생성자와 다른 현행 검토자가 명시적으로 폐기하여 학습 참조만 해제한다. 가중치·출처·평가·감사 이력은 보관하며 폐기 모델은 추론/활성화에 사용할 수 없다. 원본의 물리 삭제는 기존 용량 정책만 수행한다.

Windows에서 2GiB committed-memory, 자식 1개, CPU 약 한 코어 Job 제한을 실제 적용하고 상태로 보고한다. Linux RLIMIT 설정은 별도 OS 시험이 필요하다. 프레임워크가 없으면 `시스템에서 호환되지 않음`을 반환하며 점수를 만들어내지 않는다. 합성 데이터 정확도, loopback 지연, 소프트웨어 장애 주입 결과로 실제 고객 환경의 FPR/day, 미지 공격, 최대 EPS, 분산 HA, 전원 상실, 실장비 대응 또는 Yocto OS 이미지를 인증하지 않는다.

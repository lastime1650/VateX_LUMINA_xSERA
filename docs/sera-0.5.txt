1. 제품과 범위

제품명: Vatex LUMINA xSERA
Category: Security Evidence, Response & Automation
한국어: 보안 근거·대응·자동화 통합 플랫폼

SERA는 이 프로젝트의 통합 제품 범주입니다. 기존 SIEM 수집·검색·상관
탐지, 센서가 보고한 XDR 관측 근거, 사건 조사와 승인 대응을 연결합니다.
제품명이 바뀌어도 과거 이벤트·테넌트·계정·정책의 의미를 바꾸지 않습니다.
Splunk 비공개 코어, 상용 SIEM 전체 기능 우월성, 완성형 EDR 또는 자율
대응 인증을 뜻하지 않습니다. 실제 데이터를 표시하고 데이터가 없으면
0건·빈 상태를 보여 줍니다. 원문 JSON/SPL은 전문가 경로로 유지합니다.

0.4 콘솔 기능·조회 한도는 console-0.4.txt와 console-workflows.txt를,
새 에이전트 설치는 ../sapientia/endpoint_agent/README.txt를 함께 봅니다.
README의 0.4 이하 절은 이력이며 이 문서와 최신 검증 보고서를 우선합니다.

2. 공통 에이전트 ZIP과 장비 등록 패키지

XDR 화면에서 운영체제별 Windows/Linux 다운로드를 제공합니다. 기본
배포물은 기존 Python 3.10+ 런타임을 사용하는 소스 ZIP입니다. Python,
PyPI/OS 의존성 또는 서명된 EXE/MSI/ELF 실행 파일을 묶지 않습니다.

공통 ZIP:
- 인증된 관리자/분석가가 Windows 또는 Linux 소스를 내려받습니다.
- 등록 키, 서버 주소 설정, CA, 관리자 비밀번호를 포함하지 않습니다.
- 서버의 장비 등록 HTTPS 설정이 없어도 다운로드할 수 있습니다.
- 파일을 받았다는 사실은 장비가 등록·설치·연결되었다는 증거가 아닙니다.

장비 등록 패키지:
- 서버에 고정 HTTPS origin과 공개 CA PEM을 설정한 뒤 관리자가 만듭니다.
- platform, host, 정확한 index와 등록 유효기간을 지정합니다. 테넌트는
  로그인한 관리자의 테넌트로 고정하고 현재 인덱스 권한을 검사합니다.
- 등록 키 유효기간은 60~3600초, 기본 600초입니다. 다운로드한 ZIP에는
  deployment.json, ca.pem과 단기 비밀인 enrollment.token이 포함됩니다.
- 생성자만 해당 패키지를 다운로드할 수 있습니다. 미사용 패키지를
  다시 받으면 이전 등록 키는 교체됩니다. 사용·만료·폐기된 발급 건은
  다운로드/등록할 수 없습니다. 등록 키는 한 번만 소비됩니다.
- 등록 후 받는 별도 장비 자격증명은 90일 유효합니다. 서버에는 해시를
  보관하고 에이전트 로컬 상태는 관리자/SYSTEM 또는 root만 읽게 합니다.
- 같은 테넌트/호스트의 활성 장비를 중복 등록하려면 기존 등록을 먼저
  폐기해야 합니다. 상태 디렉터리와 장비 신원을 다른 장비로 복제하지 않습니다.

관리자는 서버 환경에 다음을 설정하고 서비스를 재시작합니다. CA 파일은
공개 인증서만 포함해야 하며 개인 키를 배포 패키지에 넣지 않습니다.

  SAPIENTIA_AGENT_ENDPOINT_URL=https://SERVER:PORT
  SAPIENTIA_AGENT_CA_FILE=공개-CA-PEM의-절대경로

서버 주소는 scheme/host/port만 허용합니다. 사용자 정보, 경로, query,
fragment를 넣지 않습니다. 장비 통신은 CA·호스트명을 검증하는 TLS1.2+
HTTPS이며 프록시·redirect·인증서 검증 해제 옵션을 사용하지 않습니다.
서버는 Forwarded 헤더를 HTTPS 증거로 신뢰하지 않습니다. 이 프로토콜을
쓰기 위해 운영자의 TLS 서비스/인증서 구성이 필요합니다. 8788은 이번
격리 검증 서버의 포트이며 모든 운영 배포의 고정 기본 포트가 아닙니다.

다운로드 응답의 X-Package-SHA256와 ZIP을 비교하고 새 비공개 폴더에
풉니다. 내부 manifest의 SHA256은 무결성 확인용이며 코드 서명이 아닙니다.
등록 ZIP을 일반 파일 서버·공개 검사 서비스에 공유하지 않습니다. 설치
성공 후 추출된 토큰 파일은 설치기가 삭제하지만 다운로드 ZIP은 운영자가
안전하게 정리해야 합니다. 원본 파일 출처/해시는 PROVENANCE.json에 있고
외부 재배포 권리는 별도 확인 대상입니다.

3. 운영체제별 설치와 수집 범위

Windows: 관리자 PowerShell에서 장비 등록 ZIP을 푼 뒤, SYSTEM이 접근할
수 있고 일반 사용자가 변경할 수 없는 Python 3.10+ 경로를 지정합니다.

  .\install.ps1 -Python 'C:\관리되는-Python\python.exe'

설치기는 ProgramData\Vatex\LUMINA\xSERA\Agent에 파일/상태를 보호하고 LocalSystem
SCM 서비스 SeraEndpointAgent를 등록합니다. 사용자 쓰기 가능한 Python
환경은 서비스 런타임으로 쓰지 않습니다. 서비스 설치 후 해당 Python을
삭제하거나 바꾸지 않습니다. 기존 설치가 있으면 자동 덮어쓰지 않습니다.
프로세스/TCP 스냅샷과 접근 가능한 기존 Sysmon/Security/Defender Event Log를
사용합니다. Sysmon을 내려받거나 EULA·감사 정책을 자동 변경하지 않습니다.

Linux: root 권한, /usr/bin/python3 3.10+, systemd를 준비한 뒤 실행합니다.

  sudo bash ./install.sh

/opt/vatex-lumina-xsera-agent와 root systemd 서비스 vatex-lumina-xsera-agent.service를 만듭니다.
/proc 프로세스/TCP 관측, 접근 가능한 systemd journal과 기존 auditd 로그를
사용합니다. audit 규칙·eBPF·커널 모듈을 설치하거나 의존성을 자동 설치하지
않습니다. systemd가 없는 장비는 별도 보호/감독 실행 구성이 필요합니다.

이 소스 패키지의 설치 스크립트 존재, ZIP/프로토콜 테스트 통과와 실제
OS 서비스 설치 검증은 다릅니다. 이번 합성 시험에서 실제 공격, Windows
SCM 설치, Linux systemd 설치, OS/배포판별 센서 전체 커버리지·대량 배포·
업그레이드를 검증했다고 해석하지 않습니다. 사용자 모드 polling은 짧게
실행된 프로세스를 놓칠 수 있습니다. 고유 PID만으로 프로세스를 합치지
않고 센서가 보고한 같은 호스트의 GUID/부모 GUID 근거를 사용합니다.

4. 등록 및 전송 API 계약

조회/발급:
  GET    /api/xdr/agents/distribution
  GET    /api/xdr/agents/packages/windows 또는 linux
  POST   /api/xdr/agents/deployments
  POST   /api/xdr/agents/deployments/{id}/package
  GET    /api/xdr/agents
  DELETE /api/xdr/agents/{id}

발급/폐기는 관리자, 공통 다운로드는 관리자/분석가, 장비 조회는 현재
테넌트·인덱스 범위를 적용합니다. 발급 본문은 platform, host, index와
선택 ttl_seconds입니다. 일반 관리자 세션 변경 작업에는 CSRF가 필요합니다.
장비/발급 목록은 권한 범위 내 활성 장비·유효한 미사용 발급을 우선하고
그다음 생성 시각 역순으로 최대 1000개를 반환합니다. count/limit/truncated/
total_at_least를 확인하며 잘린 목록의 total은 null입니다. 전체 이력이나
cursor 페이지 기능을 제공한다고 해석하지 않습니다. 표시된 collections는
해당 OS 수집기의 기능 범위이며 특정 로그가 실제 수집됐다는 증거는 아닙니다.

장비의 직접 HTTPS 요청:
  POST /api/agent/register    {enrollment_token, version}
  POST /api/agent/heartbeat   {health}
  POST /api/agent/ingest      {events: [{id, data}, ...]}
  POST /api/agent/poll        {}

등록 이후에는 전용 Bearer 장비 자격증명을 사용합니다. register 결과의
자격증명을 화면·문서·감사 본문에 출력하지 않습니다. endpoint-agent 별칭
경로도 제공하지만 설치 패키지는 위 agent 경로를 사용합니다.
장비 admission 요청은 최대 4개 작업을 동시에 처리하고, 포화 시 503과
Retry-After를 반환합니다. 등록 시도는 IP별 60초에 20회를 넘으면 429로
제한합니다. 재시도에서도 같은 이벤트 ID를 유지해야 합니다.

전송은 요청당 1~200개이며 런타임 기본 배치는 50개입니다. events의 최상위
envelope는 id와 data만 허용합니다. 테넌트/호스트/인덱스를 클라이언트가
임의로 바꿀 수 없고, 현재 등록 소유자의 관리자 역할·활성 상태·인덱스
권한과 파서 라우팅을 매번 검사합니다. 권한 폐기·등록 취소·자격증명 만료는
다음 장비 요청을 차단합니다. online 표시는 최근 접촉의 관측치이며 EDR
보호 정상 또는 악성코드 차단의 증거가 아닙니다.

에이전트는 SQLite 대기열과 안정된 이벤트 ID로 전송을 재시도합니다.
기본 대기열 한도는 10000개이며 수락과 검색 가능 시점은 구분합니다.
실패/격리 결과를 성공 수락으로 간주하지 않습니다. 서버의 영속 수락 중복
제어와 함께 at-least-once 전송을 제공하며 모든 외부 효과의 exactly-once를
보장하지 않습니다. poll 결과는 command:null, capabilities는 빈 목록입니다.
호스트 격리·해제·원격 셸·임의 명령 실행·자동 치료 경로는 없습니다.

5. 텔레메트리 → 근거/사건 → 승인 대응 → 해결

1) 등록 장비에서 실제 센서 데이터 또는 명시적으로 표시한 합성 시험
   이벤트를 전송합니다. 전송 성공 후 저장/큐 상태와 검색을 확인합니다.
2) 필드·인덱스·엔터티 조건이 맞는 상관 정책을 검증한 뒤 명시적으로
   활성화합니다. 수집됐다는 이유만으로 탐지 근거/사건이 생기지는 않습니다.
3) Command Center의 ISSUES는 저장된 탐지 근거를 보여 줍니다. 상관 근거,
   저장 검색 finding과 사건은 서로 다른 집합으로 합산하지 않습니다.
   Cases에서 실제 사건을 열고 원본 이벤트 ID·정책·타임라인·범위를 봅니다.
4) 조사 메모·북마크·우선순위/기한·담당자와 필요한 작업을 기록합니다.
   모든 필수 작업을 완료해야 해결/오탐으로 닫을 수 있습니다. 닫힌 사건에
   필수 작업을 추가하거나 다시 열려면 사건 상태를 먼저 신규/분석 중으로
   바꿉니다. 일반 메모·선택 작업의 사후 기록과 기존 필수 작업 완료는 허용합니다.
5) 순차 플레이북을 저장하고 해당 사건의 실행을 요청합니다. 요청 시
   정의 revision, 사건 버전, 전체 근거 digest와 인덱스 범위를 고정합니다.
6) 요청자와 다른 활성 분석가/관리자가 검토·승인합니다. 자기 승인, 현재
   권한이 없는 승인·실행은 거부합니다. 승인 전에는 동작을 실행하지 않습니다.
7) 런타임이 순서대로 실행하고 단계별 실제 결과를 저장합니다. 사건/근거가
   바뀌면 다음 동작은 실패하므로 새 상태를 검토하고 새로운 실행을 요청합니다.
   필수 작업이 남으면 해결 단계도 실패합니다. 실패한 실행은 수정된 상태를
   자동 승인하거나 임의로 재시작하지 않습니다.
8) 최종 해결은 사건의 실제 status=resolved로 확인합니다. 플레이북 완료,
   이벤트 수락, 위험 기여와 호스트 격리 성공은 각각 다른 의미입니다.

플레이북은 1~16단계, 정의 64KiB, 단계별 최대 시도 1~5회입니다. 지원
액션은 메모·작업·담당·상태 변경과 서버가 명시적으로 허용한 HTTPS webhook
입니다. webhook payload는 고정 값이며 이벤트 변수를 자동 치환하지
않습니다. 분기/DAG, 사람 작업 완료를 기다리는 suspend/resume, 탐지 자동
트리거와 완전 자율 대응은 제공하지 않습니다. 외부 전송 취소는 이미
발생한 원격 부작용을 되돌리지 않습니다. 결과 불명은 확인이 필요하며
피어의 명시적인 멱등 보장이 없으면 자동 재전송하지 않습니다.

명령센터 response_modes는 현재 조회 사건을 한 범주씩 나눕니다. 기록된
권한 범위 내 실행 이력의 우선순위는 executing → awaiting_approval →
attention → completed → manual → unhandled입니다. attention에는 실패·
결과 불명 및 일부 완료 후 취소가 포함됩니다. 이전 실패 이력이 새 완료
이력보다 우선할 수 있으므로 현재 센서/대응 건강 상태의 단일 점수가
아닙니다. manual은 실제 수동 액션 receipt 또는 기존 분석가 판단에서
계산하며 자동/수동 액션 개수와 사건 수를 별도로 셉니다. 화면의 흐름은
인과 추정이나 전체 공격 차단률을 뜻하지 않습니다.

6. 이번 검토에서 수정한 경계 결함

- 닫힌 resolved/false_positive 사건에 필수 open 작업을 추가하거나 완료된
  필수 작업을 다시 여는 경로를 차단했습니다. 거부된 요청은 작업/receipt를
  부분 저장하지 않고, 사건을 명시적으로 다시 열면 정상 진행합니다.
- webhook 전송 도중 분석가가 바꾼 사건 상태/담당의 version을 ACK 처리에서
  새 승인 버전으로 흡수하지 않습니다. ACK는 보존하고 다음 단계는 원래
  승인 버전을 비교하여 실패합니다. 같은 트랜잭션의 로컬 액션이 자기
  변경 버전을 다음 단계로 넘기는 정상 경로는 유지합니다.
- 공개 수동 액션 API에서 SOAR 내부 UUID:step 요청 키를 예약했습니다.
  이전 버전에서 선점된 receipt도 미완료 SOAR 단계가 발견하면 내용 일치
  여부와 관계없이 거부합니다. 수동으로 쓴 메모를 승인 후 자동 실행으로
  재분류하는 우회를 막습니다. 일반 수동 요청의 멱등 동작은 유지합니다.
  이미 완료된 과거 기록을 추측으로 재작성하지 않습니다.
- 다운로드된 configure CLI가 서버에서 허용하는 밑줄 시작 테넌트/인덱스를
  거부하던 불일치를 수정했습니다. 호스트 식별자와 테넌트/인덱스 식별자의
  서로 다른 규칙을 유지하고 서버의 정확한 허용 규칙을 따릅니다.
- 장비/발급 이력 1001개에서 목록 전체를 거부하던 경로를 수정했습니다.
  현재 권한에 해당하는 활성/유효 항목을 우선한 최대 1000개 조회와 잘림
  메타데이터를 반환합니다. 전체 이력 cursor 조회를 구현한 것은 아닙니다.

두 첫 결함은 수정 전 7개 검증 실패로 재현했습니다. 세 번째는 승인 전
수동 메모가 승인 후 soar=1/manual=0으로 집계되는 별도 최소 재현으로
확인했습니다. 새 경계 검증 13개와 기존 사건/SOAR/명령센터 회귀를 묶은
63개가 통과했습니다. 시험 데이터·계정은 운영 데이터와 분리했습니다.

7. 검증 기록과 한계

관련 pytest 63개가 통과했습니다. 새 경계 시험은 임시 저장소를 사용하고
통제된 ACK로 전송 중 상태 변경을 재현합니다. 에이전트 배포·패키지·기존
XDR 관련 별도 검증은 47개가 통과했습니다. 두 집합의 합을 전체 고유
테스트 수로 해석하지 않습니다. 최종 전체 pytest 회귀는 657개가 197.14초에
통과했고 기존 Starlette/httpx deprecation 경고 1개가 남았습니다. 검색 폼
왕복/실제 dictionary 결과 변환 Node 14개와 lookup 유형 보존 Node 8개도
통과했습니다. 관련 소규모 시험은 전체 회귀와 일부 겹치는 검증입니다.

동결 소스의 실제 다운로드된 런타임 fresh flow는 HTTPS 127.0.0.1:8788에서
21개 항목을 17.219초에 통과했습니다. 브라우저 관찰용 127.0.0.1:8790은
별도 루프백 GUI이며 장비 자격증명은 검증된 TLS 경로에만 보냈습니다.

- 실제 HTTP ZIP 10개의 응답 SHA256와 내부 manifest를 확인하고 추출했습니다.
  다운로드한 configure.py CLI를 -I로 실행해 TLS 일회 등록 8회를 수행했습니다.
  기본 테넌트의 시나리오 장비 6개, 폐기 시험 장비 1개와 별도 `_qa_other`
  테넌트/`_endpoint` 인덱스 장비 1개로 등록·권한 경계를 확인했습니다.
- 기본 테넌트 합성 이벤트 22건, 상관 근거 2건과 심각도 high 사건 2건을
  확인했습니다. 정상/시간 순서 반전의 음성 호스트 4개에서는 사건이 없었습니다.
- 각 사건에 요청자와 다른 qa_approver가 승인했습니다. 실행 2개 × 로컬
  4단계가 각각 한 번 완료되어 SOAR 액션 8건과 별도 수동 필수 작업
  receipt 2건을 확인했습니다. 최종 사건은 resolved 2개, open 0개입니다.
- 안정된 이벤트 ID 재시도·내용 충돌, ACK 유실과 로컬 큐 재시작,
  지연 도착 부모 GUID·PID 재사용, 현재 테넌트/호스트/인덱스 권한,
  CSRF/역할·자기 승인 거부, 승인 전 무동작, 닫힌 사건 필수 작업과
  예약 receipt 키 거부를 확인했습니다. 영속 대기/완료 실행을 정상
  프로세스 재시작 후 다시 확인했고 마지막 감사 체인 108개가 유효했습니다.

이 시험은 현재 검증 호스트에서 다운로드한 Windows/Linux 공통 런타임에
합성 센서 envelope를 공급했습니다. 실제 Event Log·/proc·audit 수집기와
SCM/systemd 설치, 실제 공격·외부 webhook·호스트 격리는 실행하지 않았습니다.
정상 프로세스 재시작은 전원 장애·독립 장비 HA·WORM 검증을 대신하지 않습니다.
유지된 QA 서버는 시험 환경이며 운영 배포 완료의 증거로 사용하지 않습니다.

실제 브라우저에서 Windows/Linux 공통 ZIP의 다운로드 SHA256, 뷰어의
다운로드 비활성화와 발급/폐기 컨트롤 숨김, 해결 사건의 요청자 qa_analyst와
별도 승인자 qa_approver 및 완료 4단계 표시를 확인했습니다. 390px 모바일
뷰포트에서 문서 폭 380px로 가로 넘침이 없었습니다. 해당 관찰 화면의
브라우저 오류·경고는 0개였습니다. 모든 OS/브라우저 조합의 인증을 뜻하지 않습니다.

별도 폐기 가능한 저장소의 0.4→0.5 업그레이드 검증도 통과했습니다.
기존 로그인·세션, 인덱싱/대기 이벤트 총 13건(미처리 1건 재생), 원본 ID 재전송 중복
13건, 규칙 소유자·근거·사건 작업/메모/북마크·미승인 실행·파서 revision·
baseline·엔터티·대시보드 보존을 확인했습니다. 운영 데이터로 시험하지 않았습니다.

최종 보고서에는 단위/통합 검증, 실제 TLS 전송, OS 네이티브 설치,
전체 회귀와 운영 배포를 분리해 기록해야 합니다.

계정·테넌트·인덱스 접근, CSRF, 현행 계정 재검증과 CSP는 유지합니다.
기본 콘솔 CSP는 자체 출처 스크립트/스타일만 허용하며 inline script/eval을
허용하지 않습니다. 검색·사건·그래프·콘텐츠/파서의 창·페이지·출력 제한은
0.4 운영 안내를 따릅니다. 이 버전에서 독립 장비 HA/샤딩, 전체 SPL/CIM,
고급 ML, 실제 악성코드 차단·격리, 장기간 대규모 운영이나 플랫폼별 설치
인증을 새로 달성했다고 주장하지 않습니다.

최종 축소 화면 검수에서 흐름 그래프의 가로 스크롤 뒤에 있던 처리 결과를
항상 보이는 Resolved/Open/오탐 카드로 추가했습니다. 변경 후 콘솔 관련
5개 검사를 재통과하고 새 저장소에서 21개 전체 흐름을 다시 검증했습니다.
전체 657개 회귀 결과와 이 화면 후속 검증을 구분해 보관합니다.

Vatex LUMINA xSERA 0.12.0 가상 보안 시뮬레이션
2026-10-13

1. 실행 범위

Python으로 가상 Cisco ASA, FortiGate, Windows, Linux 로거를 각각 독립
프로세스로 실행한다. 실제 xSERA FastAPI/Uvicorn, HTTPS, 인증, CSRF,
Store durable intake, background indexer/scheduler, Case, SOAR를 사용한다.
실제 장비나 호스트의 이벤트를 읽지 않는다. 로그의 명령 문자열은 실행하지
않는다. OS 방화벽/프로세스/파일, 외부 appliance/API를 변경하지 않는다.

완결된 lab 명령 (프로젝트 루트 PowerShell):

  .\.venv\Scripts\python.exe -B -m tools.simulation.run_lab `
    --work-dir C:\YourWorkspace\work\virtual-labs `
    --report C:\YourWorkspace\outputs\virtual-xdr-simulation.json `
    --count 100 --seed 17

프로젝트에 원래 포함된 Python 3.12+ 및 requirements-lock 의존성을 사용한다.
새 환경이라면 해당 의존성을 먼저 설치한다. pytest는 실행 검증용이다.

lab은 work-dir 안에 새로운 저장소와 임시 CA를 생성하며 원래 data를 열지
않는다. 임의 loopback TLS 포트를 쓰며 8787/8788은 거부한다. 임의 로컬
분석 계정 두 개를 만들고 비밀번호는 프로세스 메모리/자식 환경에만 전달한다.
프록시와 redirect를 사용하지 않고 임시 CA로 TLS를 검증한다. 완료하면
서버를 종료한다. 시험 로그·DB·CA private key가 남는 work-dir은 실험 자료로
취급하고 공유할 때는 결과 report만 전달한다. 운영 배포·서비스 설치가 아니다.

count는 장비별 5..1000. 기본 100건 중 매 5번째는 알려진 공격 모양, 나머지는
정상 twin이다. 장비별 한 번 수집하고 같은 ID/내용으로 한 번 재전송한다.
Windows/Cisco/FortiGate는 동일 보고된 src/dst IP/port/protocol을 갖고,
Linux는 다른 내부 IP다. seed와 base_time이 같으면 ID와 내용이 재현된다.
shuffle은 전달 순서만 바꾼다. 정답 label은 별도 ground-truth.json에만 저장한다.

2. 개별 가상 로거

각 wrapper는 -m으로 호출한다. 먼저 인증된 관리자 API로 source를 등록한다.
POST /api/v2/sources JSON 필드:
  index, product, account, realm, credential_ref, version
product = cisco_asa / fortigate / windows / linux
account = ASA-VIRTUAL-01 / FGT-VIRTUAL-01 / virtual-win-01 / virtual-linux-01
realm = virtual-lab, credential_ref = env:SAPIENTIA_CONNECTOR_VIRTUAL,
version = 0. 실제 secret 값을 source 정의에 넣지 않는다.
인덱스는 sim_cisco_asa 등 영숫자·underscore·hyphen만 사용한다.
개별 로거에서 해당 source ID와 현재 source/checkpoint version을 지정한다.

  $env:SAPIENTIA_SIM_USER='실험 계정'
  $env:SAPIENTIA_SIM_PASSWORD='실험 비밀번호'
  .\.venv\Scripts\python.exe -B -m tools.simulation.virtual_cisco `
    --origin https://127.0.0.1:12345 --ca C:\YourWorkspace\work\ca.pem `
    --source-id SOURCE_ID --source-version 1 --checkpoint-version 0 `
    --count 100 --seed 17 --base-time UNIX_EPOCH --shuffle --repeat 2

virtual_fortigate, virtual_windows, virtual_linux도 같은 옵션을 사용한다.
scenario 옵션은 mixed/benign/attack. batch-size 1..1000, repeat 1..10,
interval 0..60초. 원격 전달은 HTTPS와 검증 가능한 CA가 필요하다.
HTTP는 loopback 주소에만 허용한다. 패스워드는 CLI 인자로 받지 않는다.
정상 ACK 뒤만 checkpoint를 전진시킨다. 재시작 checkpoint의 durable 저장은
현재 CLI가 자동 수행하지 않으므로 최신값을 명시해야 한다.

3. 구현과 기존 기능의 연결

source_registry → connector_runtime → Store.ingest/on_admitted:
현재 사용자/tenant/index, source version, product/account/realm을 확인하고
원본 receipt와 출처 증거를 같은 transaction에 기록한다. checkpoint CAS 실패,
장비/account 위조, 원본 ID에 다른 내용, 잘못된 parser route는 batch를 거부한다.
일반 수집으로 들어온 기존 ID를 나중에 등록 source 증거로 승격하지 않는다.

Store.flush → event_projections → correlation_runtime:
실제 검색 색인 ACK transaction에서 마스킹 후 원본의 v2 분석 데이터를 만든다.
원본 receipt digest와 source authority snapshot을 보존한다. 원본 보존 잠금은
파생 데이터에도 적용되고 실제 원본/receipt가 만료되면 같이 삭제한다.
physical deletion 뒤 crash는 기존 retention intent와 admission fence로 복구한다.
Case 원본 증거/hold, 기존 security v1·SPL·정규화 경로는 유지한다.

v2 상관분석은 positive reported-flow association이라는 제한된 의미다.
같은 realm, 완전한 보고된 5-tuple, 시간창, product 역할마다 정확한 하나의
후보를 요구한다. 중복 endpoint/process 후보, 불일치, 후보 부재는 자동 연결하지
않는다. frozen seq/end, bounded page/cohort, 원본 대조, 현재 권한과 source
version을 확인한 뒤 기존 탐지 기여·Case 생성기를 사용한다. 여러 product를
각각의 역할로 검사하며 fingerprint로 replay 중복 기여를 막는다.
plan당 source 최대 16, step 8, filter 16, window 30..86400초,
within_seconds 0..300, 평가 cohort 최대 10000, page 16.
cohort 초과는 전체 결과가 완료된 것으로 표시하지 않고 error로 남긴다.
현재 집계/negative-event/absence/범용 공격 그래프 엔진이 아니다.
late indexed frontier는 현재 window 안의 기존 증거를 재평가한다.
서로 다른 clock의 offset/인과관계·NAT 소유권이 입증된 것으로 표시하지 않는다.

Case → effect_receipts → action_runtime:
정확한 Case/source/asset version, 원본 membership와 digest, 현재 ACL을 고정한다.
요청자와 다른 현행 분석가/관리자가 승인한다. 가상 effects는 Store의
simulation_mode=True 및 realm=virtual-lab에서만 실행한다. 일반 인스턴스의
기본값은 False다. 가상 상태 모델에서 변화와 재조회 결과를 hash receipt로
남기며 항상 mode=virtual, native_effect=False다. unknown dispatch를 반복하지
않는다. confirmed 재시도는 상태 효과를 중복 적용하지 않는다.
isolate_host/release_host: Windows/Linux, lease 5..300초, 정확히 소유한 해제.
terminate_process: Windows/Linux의 보고된 GUID/PID/start incarnation과 모델 일치.
block_ip/unblock_ip: Cisco/FortiGate의 원본 IP 증거와 소유 receipt 일치.
활성 임대는 다른 action으로 덮어쓰지 않는다. 만료 여부는 effective 조회에 반영한다.
유한 가상 임대는 실제 장비 watchdog/네트워크 효과의 검증이 아니다.

SOAR는 기존 독립 승인 add_note/add_task 실제 API·worker·Case mutation을 검증한다.
외부 제품 호출은 하지 않는다. v2 모델 효과는 별도의 승인 실행 경로이며 기존
SOAR에 새 외부 DAG/action provider가 통합됐다는 뜻은 아니다.

4. 다른 제한된 신규 계약

release_manifest: 현재 authored source/규칙/테스트/docs/lock의 SHA256 identity.
pyproject/module 버전 일치 검사, package manifest release/wire ID 및 code_signed,
native_qualified=False. 패키지 공개키/실제 OS code signing은 별개다.
migrations: immutable per-component checksum, transaction/savepoint, 순차 적용,
startup 전 unsupported version 거부. 구 binary의 destructive downgrade는 금지한다.
qualification_registry: pinned Ed25519 signer·범위·source/package/config/tool hash,
expiry와 passed/native 조건의 별도 record/check. 실제 기존 native adapter의 모든
실행 지점에 qualification gate가 연결된 완성 상태는 아니다.
sensor_capabilities: typed loss/reset/backlog·clock interval·unknown 계약 및 테스트.
기존 모든 native collector의 loss 계량/heartbeat 배포는 추가 작업이다.
CloudTrail 1.x individual record parser는 recipient account를 source에 묶고 caller
account/STS identity와 원문을 별도 보존한다. 내부 서비스 문자열을 IP로 추정하지
않는다. 현재 Store 64 KiB 한도를 넘는 원문은 자르지 않고 거부한다. S3/SQS 폴링,
provider digest 검증, 대형 원문 blob, EDR/IdP SDK integration은 추가 작업이다.

5. 판정

결과 JSON은 수집/중복/색인/실제 Case·SOAR/원본 tuple TP·FN·unexpected evidence,
9개 가상 상태 효과와 native=false/hidden_holdout=false를 기록한다.
알려진 합성 시나리오의 성공을 실제 센서 포착률·MITRE native coverage·상용
XDR 탐지/차단 성능·독립 holdout 정확도·대규모 HA 인증으로 확대하지 않는다.
개선 설계 전체 21개 항목의 진척은 별도 구현 대조 보고서에서 판정한다.

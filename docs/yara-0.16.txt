xSERA 0.16.0 — 프로세스 바이너리 YARA 분석

목적과 처리 경로
프로세스 실행파일을 에이전트에서 수집하고 CPU 기반 YARA로 정적 검사한다.
실행 중인 프로세스 메모리 덤프나 샘플 실행 기능은 포함하지 않는다.
원본 로그 → 정확한 프로세스 인스턴스 확인 → 실행파일 SHA256 확인 → 에이전트 수집 요청
→ 인증된 분할 전송 → 전체 SHA256 검증 → 자동 YARA 검사 → Case 분석 이력·공통 탐지 신호.

웹 콘솔
YARA 분석 메뉴에서 기본팩과 사용자 규칙을 검색하고 원본·출처·라이선스를 확인한다.
GUI 빌더는 텍스트/HEX 패턴, 모두/하나 일치 조건, PE/ELF 형식과 최대 파일 크기를 지원한다.
고급 편집기에서 실제 YARA 소스를 수정하고 서버 엔진으로 컴파일 검증한다.
관리자는 사용자 규칙 생성·수정·제거·복원을 수행한다. 변경된 규칙은 작성자와 다른
관리자가 검토해야 활성화된다. 엔진 미설치 상태에서 보관한 초안은 실제 컴파일 검증을
통과해야 활성화할 수 있다. 보기 권한과 분석 실행 권한은 기존 역할·인덱스 권한을 따른다.
기본팩의 원본 파일은 보존한다. 기본 규칙 변경·제거는 전체 범위 관리자에 의한
테넌트별 재정의이며 복원하면 배포된 원본을 다시 사용한다. 범위별 사용에는 복제를 사용한다.
규칙의 제거는 활성 사용에서 제외하는 동작이며 과거 개정·감사·검사 결과는 보존한다.

에이전트 수집
Case 원본 중 등록된 에이전트의 수집 영수증이 검증된 프로세스를 선택한다.
PID, 시작 식별자, 프로세스 GUID, 절대 실행파일 경로와 SHA256을 고정한다.
SHA256 없는 원본은 명시적 실행파일 정보 확인 요청을 먼저 보낸다. 결과는 새 원본 로그로
수집되며 기존 원본을 수정하지 않는다. 새 원본을 사용자가 Case에 참조로 추가한 후 수집한다.
사용자가 임의 경로·해시·실행 명령을 넣는 수집 요청은 허용하지 않는다.
에이전트는 allow_investigation, allow_process_artifact_collection과 정확한 실행파일
허용 목록을 로컬 설정으로 활성화해야 한다. CLI의 --allow-process-artifact-collection은
읽기 전용 실행파일 관찰·수집용이며 프로세스 종료·파일 삭제·호스트 차단을 활성화하지 않는다.
현재 프로세스 인스턴스와 경로를 다시 검사하고 파일 변경·심볼릭 링크·재분석 지점,
해시 불일치나 크기 초과가 있으면 실패한다. 프로세스 바이너리 최대 32MiB, 기존 일반
파일 수집 최대 2MiB이며 전송은 32KiB 단위로 진행한다. 완료 이전 파일은 분석에 쓰지 않는다.
기존 중요 OS 프로세스·관리 프로세스·에이전트 및 상위 프로세스 보호를 유지하며,
다중 하드링크 실행파일도 거부한다. 전체 시스템 바이너리를 무조건 수집하는 기능이 아니다.

규칙과 결과
공개 규칙은 검토한 상위 저장소의 고정 커밋에서 다운로드한 소스다. 라이선스가 불명확하거나
재배포 조건이 맞지 않는 파일, 외부 변수·include·import 모듈에 의존하는 파일,
컴파일 오류·경고가 발생하는 파일 등은 기본 탐지팩에서 제외한다. 실제 제공 파일 수와
규칙 수, 제외 사유는 규칙팩 manifest 및 콘솔 상태 API가 기준이다.
여러 규칙을 담은 한 소스 파일의 내부 의존성을 보존하며 파일마다 별도 namespace를 사용한다.
규칙 작성자·라이선스·출처·원본 해시를 보존하고 일치 결과에도 저자와 출처를 포함한다.
규칙팩의 규모는 탐지율이나 미지 공격 탐지 성능을 증명하지 않는다. 운영 오탐은 환경별 검증이 필요하다.

검사는 서버의 별도 프로세스에서 수행한다. 규칙 소스 한 파일 32KiB, 전체 4096개 파일·16MiB,
바이너리 32MiB, 검사 작업자의 전체 벽시계 제한 15초와 YARA 매칭 제한 5초를 적용한다.
서버의 YARA 컴파일·검사는 동시에 한 작업씩 수행해 수집·ML 작업자와 분리한다.
시간 초과·미설치·검사 실패는 별도 상태이며 정상이나 깨끗한 파일로 표시하지 않는다.
일치하지 않은 파일의 판정도 unknown이다. 일치 결과는 suspicious 정적 서명 근거다.
자동 검사는 명시적으로 수집을 요청한 process_executable 아티팩트에 한해 한 차례 처리하며,
일반 파일은 콘솔에서 검사한다. 별도 규칙 선택 또는 전체 활성 규칙으로 재검사할 수 있다.

탐지와 Case
검사 이력에는 원본 이벤트, Case, 아티팩트 SHA256, 사용 규칙 개정·해시와 실행 상태를 기록한다.
일치 시 kind=finding, rule_id=yara:binary, severity=high 신호를 발행한다.
signal.features.yara_match_count 및 artifact_sha256을 복합 정책에서 사용할 수 있다.
기존 행위·ML 신호와 결합해 승인된 복합 정책 및 Case 연결 조건을 충족하면 후속 탐지에
활용한다. YARA 신호는 장치 대응 권한이 아니며 자체적으로 차단·종료·삭제하지 않는다.
분석 도중 권한·원본·아티팩트·규칙 개정 또는 승인 상태가 바뀌면 결과 발행을 중단한다.
기록 관리 내보내기는 yara_runs, yara_rules, yara_rule_history를 제공한다.

운영 범위
운영 데이터 저장소를 여는 작업이나 실장비 차단 시험을 수행하지 않고 격리된 임시 저장소와
무해한 바이트로 검증한다. 실제 장비 전송 품질과 장기간 오탐률, Yocto 이미지의 패키징·자원
인증은 별도 검증 대상이다. 기존 2MiB 분석·외부 샌드박스 경로는 큰 프로세스 바이너리를
명시적으로 거부하며 전용 YARA 경로를 사용하도록 안내한다. 바이너리를 외부 서비스로 보내지 않는다.

COMPATIBILITY, QUALITY AND EXCLUSION POLICY
------------------------------------------

The manifest records every reviewed file, its pinned upstream Git blob, source
SHA-256, decision, reason, and recognized license declarations. Accepted entries
also record individual rule identifiers, authors, metadata, tags, private/global
flags and actual compiler results.

Each accepted file remains byte-for-byte identical to its upstream Git blob.
No source flattening, directive removal, rule splitting, identifier rewriting,
binary sample download, binary execution or repository-script execution occurs.
Complete files preserve private helpers and global-rule scope. Separate runtime
namespaces prevent identifiers in different upstream files from colliding.

The importer excludes:
  - Different, ambiguous, research-only or noncommercial license declarations.
    Other permissive licenses await their own obligation review.
  - Sources exceeding 32 KiB or containing unsupported control characters.
  - Any case-sensitive include/import word, matching the conservative runtime
    policy. This can also reject words inside comments or strings.
  - Missing external variables, syntax errors, compiler warnings, unresolved
    dependencies, failure of the harmless probe or the three-second validator.
  - Files containing no public rules.
  - Public constant-only, file-size-only or header-only conditions.
  - Explicit INFO/informational/filetype/test/dummy rules.
  - Duplicate exact source bytes, if encountered.

Whole files are excluded when an embedded rule fails these checks; rules are
not edited or extracted to increase the count. Stale excluded .yar/.yara files
are removed from the owned output directory rather than shipped unreferenced.

VERIFIED BEHAVIOR AND LIMITS
----------------------------

The real yara-python 4.5.4 engine compiled all 991 files together in distinct
namespaces and reported exactly 2,285 definitions, including 2,276 public rules.
A harmless byte-string probe matched none. A separate inert literal-path oracle
matched an existing upstream JNDI-pattern rule and retained its supplied author.
These checks exercise compilation, compatibility, matching and attribution.
They do not establish real-world false-positive/false-negative rates, detection
of an unknown threat, or verified malware execution.

The catalog loader verifies a source-code-pinned manifest SHA-256, each source
SHA-256 and original license notices. It returns independent caller objects.
It opens no Store, reads no operational telemetry, activates no response, and
does not send a sample or rule to an external service. A catalog match requires
context and review; no match does not certify a clean file.

The catalog's own offline compile/probe runs in an isolated child with a
three-second outer bound and one-second match timeout. Windows uses the actual
base interpreter with the trusted current environment's site-package paths,
avoiding a venv-launcher descendant surviving a timeout. The separately managed
file-scanning runtime owns its own sample bounds, deadlines and verdict policy.

REPRODUCIBLE MAINTENANCE
-----------------------

Offline verification, from the project environment:
  .venv\Scripts\python.exe -m tools.import_yara_catalog --validate

Explicit pinned text fetch and rebuild:
  .venv\Scripts\python.exe -m tools.import_yara_catalog --fetch ^
    --staging <owned-staging-directory> --output sapientia/catalogs/yara

The script fetches only .yar/.yara and top-level LICENSE/README text from the
four locked commits. It verifies their Git blob hashes before including them.
No access token, malware sample, executable or remote script is fetched.
The staging directory is a maintainer workspace, not operational data.

Rebuilds record their capture time and consequently produce a new manifest
digest. Review the resulting decisions and counts, pin the approved digest in
sapientia/yara_catalog.py, run tests/test_yara_catalog.py and offline validation,
then rebuild and verify the release package. Runtime updates do not fetch from
GitHub or silently replace this pinned catalog.
